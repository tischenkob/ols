## Compile gate

- **`odin check` is sometimes killed by signal 11 with no output, so the gate reports "did not run" instead of rolling back.** Seen in Skald (58 packages, `ols query attr add skald/text.odin:L:1 deprecated=1 --apply` on a copy, which must roll back with exit 4): 6 of 40 runs, and 6 of 60 in another batch, failed the check before or after the write ("refused, nothing written" or "printed nothing after writing"). A debug print in `check` showed the failing process with `exit_code = 11`, about 10 ms of CPU and an empty buffer, for packages such as `examples/09_widgets` and `examples/48_audio`, so a different package each time. `record_check_run` in `src/server/rols_check_run.odin` reads this correctly: no output and a non-zero exit. The cause is the child, not the pipe read: 700 plain `odin check` runs of the same packages with 10 in parallel (a loop outside ols) did not fail, and the final drain read in `check` returns EOF, not an error. `core:os` `_process_wait` (`process_posix.odin:323-325`) stores the signal number in `exit_code` for a killed child, so `exit_code = 11` with no output is almost certainly SIGSEGV in the forked child or in `odin`. Unproven whether the child crashes in the fork before `execve` (`core:os` `process_start` runs non-async-signal-safe code there) or `odin` crashes at start. A bounded retry of a process that exits non-zero with no output would hide it, and the retry would not explain it. Next step: run the loop with a `posix_spawn`-based launcher or log the signal with `waitpid` to split the two.

## Edits (stage S9)

- **Organize imports still adds imports above the first import.** `organize_import_edits` in `action.odin` (upstream) does not use `import_group_offset`, which the code actions and modernize now share.
- **"Add explicit type" writes the variable name for a local declared with an inline aggregate type.** `p: struct { a: int }` followed by `x := p` becomes `x: p = p`. The symbol that `p` resolves to is named `p` and has no `.Anonymous` flag, so `symbol_type_text` in `rols_edit.odin` takes the name for a type. A field or element of an anonymous type (`s.inner`, `arr[0]`) is refused since the `.Anonymous` check in `symbol_type_text`. The flag is probably lost where a local's type expression is resolved in `analysis.odin` (upstream). Unverified for inlay hints and the other `symbol_type_text` callers.
- **The fill broadcast is withheld for element types where Odin may reject an untyped value.** `broadcasts` in `rols_lint_use_stdlib.odin` keeps `slice.fill` for matrix and enumerated-array elements and for `nil` into a union, even when the value is typed and a broadcast would compile.
- **The fill rewrite accepts a value that reads an element through a pointer field or a call.** `reads_array` in `rols_lint_use_stdlib.odin` refuses an index, slice or deref through a pointer, but not a field read through a pointer to an element: `p := &items[0]; for &e in items { e = Item{x = p.x * 2} }` is still offered, and the rewrite reads `p.x` once. A value that calls a procedure that reads the array escapes the check the same way.
- **"Expand compound assignment" leaves an `or_return` operand unparenthesised.** Its wrap list in `rols_action_rewrite_expression.odin` covers ternaries and `or_else` but not `Or_Return_Expr` or `Or_Branch_Expr`, so `x += f() or_return` becomes `x = x + f() or_return`, which Odin rejects. `operand_text` in `rols_action_split_merge_if.odin` has the full list.
- **A builtin `use-stdlib` target declared in another file of the package still captures the call.** `stdlib_matches` in `src/server/rols_lint_use_stdlib.odin` drops a builtin match (`max`, `min`, `abs`, `clamp`, `copy`) when `name_taken` finds the name in the open file, including the enclosing procedure and its locals. A package-level `max` declared in a sibling file is not seen, so the rewrite would call it. Closing it needs a lookup in the package index.

## Lints (`src/server/rols_lint*.odin`)

- **Dead-store matches a `defer` by name only.** `deferred_mention` in `src/server/rols_lint_dead_store.odin` keeps a store silent when a `return` or branch lies between it and the overwrite and a `defer` written earlier in the procedure mentions the name, even a `defer` in a block that has already closed or one that names a shadowed variable.
- **The `range-off-by-one` guard through a local length matches by name.** `names_len_local` in `src/server/rols_lint_loops.odin` accepts any earlier `n := len(x)` in the same top-level declaration, so a shadowing `n` or a later `n += 1` still counts as a guard. A length held in a parameter or a struct field is not seen. The guard check ignores the operator and the comparison direction, so `if b < len(x) || x[b] == 0` and `if b > len(x) { x[b] }` count as guarded. A use in the `if` init (`if v := x[b]; b < len(x)`) also counts as guarded.
- **`pure-call-unused` judges a pointer variable argument by name lists only.** `strings.to_reader`, `to_reader_at`, the `intern_` procs, `to_cstring` and the `*_iterator` procs are now exempt by name in `src/server/rols_lint_pure_call.odin`. Another pure-package procedure that writes through a pointer variable (not `&x`) still reports. A rule for any pointer-typed argument would also hide real pure calls, so each new case needs a per-proc judgement.
- **`PURE_PACKAGES` lists `/slices`, but the core package is `core:slice`.** `lint_pure_call` in `src/server/rols_lint_pure_call.odin` therefore never checks `slice.*` calls. Unverified whether this is deliberate.
- **A bare-bool or numeric constant is not named-checked.** `is_enabled :: true` is classified as an alias, so no naming rule applies. `count :: 5` still must be SCREAMING_SNAKE_CASE.
- **`make-len-append` recognises only a written `[dynamic]T`.** `make_len_append` in `src/server/rols_lint_allocator.odin` skips `Array :: [dynamic]int` followed by `make(Array, 4)` and `append`. The allocator-mismatch check now resolves a named type through `lint_symbols`; the same lookup would close this.
- **The ignored-result proc-type check and `compares_non_bool` build a fresh `AstContext` per hit.** `names_proc_type` in `src/server/rols_lint.odin` runs only for `Err`-named results, and `compares_non_bool` in `src/server/rols_simplify.odin` for comparisons with `true` or `false`. `LintContext` could carry the walker's context instead.
- **`bool-compare` keeps the comparison for every non-`bool` boolean operand.** `compares_non_bool` in `src/server/rols_simplify.odin` also keeps `if b32_value == true`, where dropping it is harmless. It judges identifiers, selectors and single-result calls only.
- **`redundant-type-assertion` only matches a plain identifier subject.** `switch _ in x.shape { case Circle: c := &x.shape.(Circle) }` is not reported. `match_switch_binding` in `src/server/rols_lint_redundant_type_assertion.odin` proves the subject by name, so a selector subject also needs a check that no part of the chain is written in the clause.
- **`unused-parameter` sees value uses of a procedure only in its own file.** `value_names` in `rols_lint.odin` walks the open file once. A handler that another file of the package registers still reports. Closing the gap needs a scan of the package's indexed files, so the lint would pay that cost for each file it checks. A same-named local that resolves to a procedure also counts as a use, and a mention that resolves to a variable does not.
- **The `unused-parameter` rename fix checks named arguments in other files only as an editor quick fix.** The lint drops the fix when any call in the same file names an argument like the parameter, whatever the callee. `named_elsewhere` in `src/server/rols_action_lint_fix.odin` adds a workspace reference search, but only when the client asks for actions at the parameter. `ols query modernize --rule unused-parameter` and the review set still see the same file only, so a call in another file that names the argument breaks; the CLI compile gate catches it and rolls back. A call through a procedure group in a file that does not reference the procedure is not seen.
- **The multi-value expansion counts a group call by the members the whole-file resolve kept.** `arg_results` in `src/server/rols_lint_printf.odin` (shared by the printf and argument-count lints) uses the result count when every kept member agrees, and skips the count checks of the call otherwise. Because the resolve skips the arity filter, it can keep one member that does not fit the call, and then that member's count is used. A callee that does not resolve, or a group that only resolves without the call, is resolved again in a fresh package `AstContext` per argument (`group_results`), so a local that shadows a global group reads as the global.
- **The multi-value expansion counts any callee that is not a name as one value.** `arg_results` in `src/server/rols_lint_printf.odin` counts a conversion such as `(^int)(p)` correctly, but also counts `(f)()`, `f()()` and `arr[i]()` as one value although their result count is unknown. The resolve map holds named callees only. This predates the group counting.
- **printf does not consume an argument for an unknown verb.** core:fmt reads the argument for `%k` and prints `%!k(…)`, while `consume_verb` in `src/server/rols_lint_printf.odin` reports the verb and leaves the argument unread. `fmt.printf("%k", x)` therefore also reports `x` as an extra argument.
- **Enum switch coverage treats a member value it cannot evaluate as distinct.** `enum_member_values` in `src/server/rols_layout.odin` (shared by `redundant-partial` and the populate-switch-cases action) evaluates integer constants in the enum's package and recognises a bare reference to an earlier member. A value it cannot evaluate, such as `LAST = C + 0` or a constant that does not resolve, gets its own case, so the action may still emit a duplicate for it. A constant that resolves to the wrong declaration gives a wrong value, which can merge two members or split an alias from its target; `const_int` relies on `resolve_type_expression` to find the declaration.
- **Unused imports count a package named in either branch of a `when` as used.** `odin check` checks only the taken branch, so it reports `core:hash` in `internal/engine/unload.odin` of the sweep project when every `hash.` sits under a false `when hostabi.CHECKED`. `find_unused_imports` in `src/server/imports.odin` walks both branches on purpose, because organize-imports on save would otherwise delete an import that another build configuration needs.
- **Two imports of one package path count as one.** `find_unused_imports` keys used packages by path, so `import "a"` and `import b "a"` are both used when either name appears. Odin reports the unused name.

- **The nested-if merge refuses a deferred callee only when it resolves.** `merge_calls_deferred` in `src/server/rols_action_split_merge_if.odin` reads the whole-file resolve map, so a call whose callee does not resolve, or a call through a procedure group, still merges even if the procedure has a `deferred_*` attribute. The other rewrites that write `&&` or `||` (the De Morgan rewrite in `rols_action_rewrite_expression.odin` and invert-if) only reshape an existing logical expression, so they cannot introduce the error.

## Safe-rename check (`src/server/rols_rename_check.odin`)

- **Field renames still read every workspace file.** `check_embedders` passes `require_text = "using"` to `find_symbol_references`, so a file is parsed only when it mentions both the owner type and `using`. The search still reads every file to test that. On 200 files that mention the type, the dry-run `ols query rename` of a field took 0.50 s before and 0.33 s after. A cached word index of the workspace would remove the reads.
- **`using` statements are found only in files that name a carrying type and contain `using`.** `check_using_statements` reads the documents `check_embedders` collects. A `using x` where `x` gets its type from a call, in a file that never names the type, is not checked.
- **Field captures skip uses that already resolve to a field, and alias embedders are missed.** `field_captures` skips a use of the new name that resolves to a `.Field`. Given `proc(using bar: Bar)` with `Bar.limit`, and then `{ using foo; _ = limit }` in its body, renaming `Foo.x` to `limit` misses the capture. `Alias :: Foo` with `using a: Alias` is not followed as an embedder; this predates S5.
- **Implementation requests on a procedure still run a workspace reference scan.** `proc_group_locations` in `src/server/rols_implementation.odin` calls `find_symbol_references`, which now skips a file that has no `proc` followed by `{` (`require_proc_group`), but still parses every other file that names the procedure. The measured gain was not taken on a large workspace.

## Edits (stage S10)

- **"Add ok result" refuses every caller shape it cannot extend.** It adds `, _` to `v := f()`, `v = f()`, `a, b := f()` and the `if` init form, leaves a statement call alone, and refuses the whole action for a call used as an argument, a return value, an `or_return` operand, a typed declaration, a named-argument call and a procedure used as a value. `#optional_ok` would keep most of those compiling but changes the result type the tests expect. A local procedure is refused when its name appears anywhere else in the file.
- **"Add defer <free>" trusts every statement call except the append family not to keep its argument.** `escapes_from` in `src/server/rols_action_defer_delete.odin` refuses when the variable, or a value derived from it, is returned, stored, used as a map key, reassigned or passed to a call whose result is kept. A call such as `register(&list, s)` whose result is discarded may still store `s`. Only `append`, `append_elem`, `append_elems`, `inject_at`, `assign_at` and `map_insert` are known to store an argument. Aliases made by a range loop are not tracked: `for &e in s { g = &e }` stores a pointer into `s` through `e`. The walk is also conservative: `y := p.x` and `n := f(s)` refuse the action even when the copy shares nothing.
- **"Add ok result" does not look past the workspace.** `find_call_sites` reads the workspace files, so a caller in a package outside the workspace folders still breaks.
- **"Unwrap block" treats only a direct `return` or branch statement as terminating.** `unwrap_leaves_dead_code` in `src/server/rols_action_unwrap.odin` does not see `if c { return } else { return }`, `panic(...)` or `os.exit(...)` as a terminator, so unwrapping a body that ends that way can still leave unreachable statements. The action also refuses when `enclosing_stmts` finds no statement list, such as an `if` in an `else if` chain.
- **"Convert to C-style for" evaluates the high bound on every iteration.** `add_c_style_for` in `src/server/rols_action_expand.odin` copies the bound into the condition, so `for _ in 0 ..< len(x)` becomes `i < len(x)`. A range loop evaluates the bound once, so a body that changes `x` runs a different number of times after the conversion. Hoisting a non-constant bound into a local before the loop would keep the behavior.
- **"Inline procedure call" refuses on any identifier match.** `borrows_from_file` in `src/server/rols_action_inline_proc.odin` does not track shadowing, so a parameter or local named like a file-private declaration or an import of the callee's file refuses the action. It does not add the missing import for the caller.
- **"Inline variable" refuses more than it must to keep evaluation order.** An initializer moved past a statement must hold no call (builtins such as `len` included), no index, slice or deref, no `context`, no selector on a variable or parameter, no global read and no name the resolver misses (`reads_state` in `src/server/rols_action_inline_variable.odin`). An initializer that fails this is inlined only into the next statement, where nothing before the use may call or read any variable other than a plain local `=` or `:=` target (`evaluated_in_place`). So `v := f(); g(a, v)` is refused for a local `a`, `v := bump(); counter = v` is refused because `counter` is a global target, and `n := len(s)` across a statement is refused. A literal initializer with more than one use is refused, as is a read of a `using` field. A purity table for builtins and a type check for value-typed locals would widen it. An unresolved callee name such as `bar` in `bar(v)` is still accepted, because compiling code can only call a procedure there.
- **"Generate test" refuses a result whose zero value needs a package-qualified type.** `result_checks` in `src/server/rols_action_generate_test.odin` spells an aggregate as `T{}` because `testing.expect_value` cannot infer a bare `{}`. For `time.Time` the test file would need the import, so the action is withheld instead. The action is also withheld for a result that `testing.expect_value` rejects as not comparable, such as `any`, a struct holding a slice, a `#raw_union` struct, a `#soa` fixed array or a fixed-capacity dynamic array; a field assertion per member would lift it.
- **"Generate test" deletes every slice, dynamic array and map result.** The stub writes `defer delete(result)` and `testing.expect(t, len(result) == 0)`. A procedure that returns a view into memory it does not own, such as a sub-slice of a global, gets a test that frees memory it must not free; the author edits the stub.
- **"Generate test" names the test of an OS-suffixed file so that it builds on every target.** For `x_windows.odin` it writes `x_windows_test.odin`. `file_name_target` in `src/server/build.odin` reads only the last two `_` segments, `windows` and `test`, and `test` is no OS or architecture, so it finds no target suffix. `odin check` on macOS agrees: it builds `x_windows_test.odin` and skips `x_windows.odin`. The test then calls a Windows-only procedure on every other target. The new file copies the source's `#+build` lines, but not the constraint that the source's file name carries. "Move to new file" already keeps it by appending `target_suffix` (`src/server/rols_move_decl.odin`) to the new name. A test name such as `x_test_windows.odin`, built from that helper, or a `#+build windows` line in the new file would keep it here too.
- **Slicing resolves to an anonymous slice type.** `resolve_slice_expression` in `src/server/analysis.odin` now clears the symbol's name and pointer count, so hover and "Add explicit type" print `[]int` for `s.arr[:2]` instead of the field name. The upstream test suite passes, but a client that read the old name from a hover will see a different text.
- **`rename-package` rewrites a bare package name only as the value of a declaration.** `alias :: old` is rewritten. Any other bare use of the name is left alone because it may be a field or a local.
- **`borrows_from_file` checks one direction.** A local, file-private declaration or import in the caller's file that shadows a package name the copied body uses is not detected. Same-file inlining had this gap before.
- **Generated `T{}` can still fail.** `testing.expect_value(t, x, T{})` does not compile when `T` is file-private in its source file or has slice or map fields, which are not comparable.
- **"Remove redundant else" is refused when the `if` is not the last statement of its block.** This follows from the guards shared with the simplify rule.
- **"Add ok result" refuses any procedure with `or_return`**, because `or_return` assigns the operand's end value to the last result and Odin rejects `Err` to `bool`.
- **A `distinct bool` result is not read as an ok flag.** `result_kind` in `src/server/rols_action_result_handling.odin` matches only the names `bool`, `b8`, `b16`, `b32` and `b64`. "Add ok result" is still offered on a procedure whose last result is `My_Ok :: distinct bool`, and the result-handling actions treat that result as `.Other`. Resolving the type to its base would lift it.
- **`builtin_without_decl` accepts any declaration of a builtin name.** `symbol_type_text` in `src/server/rols_edit.odin` qualifies a builtin type name when the package declares that name, whatever the declaration is. A procedure or variable named `string` in the package, or a `@(private = "file")` alias `int :: i32` in another file, makes a builtin result print as `pkg.string` or `pkg.int`, which does not compile. Requiring a non-private type declaration would close it.
- **"Convert to switch" misses an unlabeled `or_break` in the header of a nested loop or switch.** `breaks_enclosing` in `src/server/rols_action_switch.odin` skips a nested `for`, `switch` and their kin whole, header included. An `or_break` in that header, such as `for x in f() or_break {}` or `switch g() or_break {}`, targets the loop around the `if`, so after the conversion it would exit the switch instead. Verified with `odin run` for a range header on 2026-10-06; the other header positions are unverified. The fix walks the header fields that run before the nested statement (`init`, range `expr`, switch `tag` or `cond`) before skipping its body.

## CLI queries (`src/cli/rols_cli.odin`, `src/server/rols_find.odin`)

- **`lint DIR` and `check` filter directories, not files.** `package_dirs_below` keeps or drops whole directories, and `collect_lints` then globs every `.odin` file of a kept directory, so a gitignored file inside a kept directory is linted, and the `DIR` given on the command line is never filtered. Filtering files in `collect_lints` would change `check` too.

- **`check` and `tests` in a directory without `.odin` files cover every package of the root, with one `odin check` per package.** The run gets the 20 s of an editor check for each batch of cores packages, capped at 10 minutes (`gate_check_timeout`), and the packages share no cache, so a large repository takes long.
- **`checker_skip_packages` compares the literal path.** The CLI resolves symlinks in its paths, so an entry that goes through a symlink such as macOS `/var` or `/tmp` never matches, and `ols query check` still checks the package. The smoke case `check-skipped-package` passed only because `check` always exited `0`.
- **`find` parses every workspace `.odin` file on each call.** The LSP workspace symbols read the index, which parses each package once. `find_symbols` reads all files again, so a call on a large tree such as Odin's `core/` costs one parse of the tree. A cache across calls does not help a one-shot CLI process.
- **`find` does not evaluate `when` conditions.** It reports a declaration in every branch of a `when` block, so the branch that the target does not take shows without a mark. The index evaluates the conditions it can.
- **`tests FILE` drops a file that the target does not build.** `odin test -file` may still build a file with `#+build` tags that exclude the host; this was not checked.
- **`lint` says nothing about a file that does not parse.** It prints the lint, unused and unused-declaration diagnostics, not the parser's, so `lint DIR` over a package with a broken file reports only the other files and exits `0`. `modernize` notes such a file as skipped on stderr.
- **`test DIR NAME` checks the names against `find_tests` before it starts `odin test`.** An `@(test)` in a `when` branch counts whatever the condition, so a name from a branch that the target does not take passes the check and `odin test` then reports "No tests to run" with exit `0`.

## CLI compile gate (`src/cli/rols_apply.odin` `run_edit`)

- **The gate checks only the targets that touched files and target-less importer directories need.** A sibling file that the host excludes, such as `lib_windows.odin` next to an edited `lib.odin`, and the excluded files of an importer directory that also has a host file are not checked on their targets. A break there passes the gate unless `checker_targets` names the target.
- **Every extra target checks every package.** `gate_targets` in `src/cli/rols_gate.odin` returns one list, so a `_windows.odin` edit in a workspace with many importers runs all packages again for `windows_amd64`. Checking only the importers of the packages that need the target would cost less.
- **An extra target drops a package only for an error outside the workspace.** `gate_baseline` in `src/cli/rols_gate.odin` skips a package on an extra target when its baseline check there names a file outside the workspace. A package that does not build on that target but whose errors are all in workspace files stays gated, and its error set can still change between runs. A package that does build there but already reports an error inside a core generic loses its gate on that target. Dropping a package costs a second baseline run of that target.
- **The rename rewrite uses lines, not columns.** `on_edited_line` in `src/cli/rols_gate.odin` lets a before error on a line the rename edits match the renamed form. An unrelated error on the same line still can. An error whose position is on another line of a multi-line call is not rewritten.
- **The summary does not name the targets the gate checked.** `rename: … written, 1 package checked` reads the same whether the gate also checked `windows_amd64` for a `_windows.odin` file or not, so a user may believe a target-only file went unchecked. A scratch package with a recipe that breaks `x_windows.odin`, or a `#+build windows` file, rolls back with exit `4` on a darwin host, so the gate does check it. Naming the extra targets in the summary would remove the doubt.
- **The style rerun ignores the concurrency cap and any genuine Syntax Error also pays for it.** `check` starts reruns beside the regular processes, and the whole run gets `2 * timeout` (not one extra per rerun). A file with a real syntax error always runs twice.

## Large-file performance (stage S15)

- **Opening a 2 MB file still takes 1.3 to 2.4 s.** On `core/rexcode/isa/ppc/mnemonic_builders.odin` (13,308 declarations), `didOpen` spends about 0.3 s parsing and about 2 s in `resolve_entire_file` for the lints. The stacks show no single hot spot: `clone_node`, `resolve_function_overload`, `create_uri` and `store_local` each hold a few percent. A request on that file after the open takes 0.2 s or less (codeAction 1.5 s total, documentSymbol about 1.6 to 2.1 s, inlayHint 1.8 s).
- **Code actions still recompute `lint_fixes`, `simplifications` and `stdlib_matches` per request.** After the quadratic lint scans went, a code action on the 2 MB file costs 0.2 s or less beyond the open, so no cache was added. Revisit if a file with many more lint hits shows up.
- **`find` parses every workspace file once per call.** `find_symbols` in `src/server/rols_find.odin` took 0.22 to 0.27 s over this repository's 300 files. A text prefilter would have to follow the fuzzy matcher, so none was added.

## Test harness (`build.sh`)

- **A test that panics or faults never ends in the agent sandbox (found in S16).** `invert_if_early_exit_do_body` at `c5c8fa27^` printed `Invalid slice indices 61:60 is out of range 0..<83` and then spun at about 60% CPU, so the bounds check did panic. A scratch Odin test with a plain `panic("boom")` or an out-of-range index hung the same way. A C program whose `SIGSEGV` and `SIGTRAP` handlers run `write(2, "hit\n", 4); _exit(42);` printed nothing and was still spinning when a 10 s alarm killed it (exit 142), for a null write and for `__builtin_trap()`. So in the sandbox the handler is not reached, and the faulting thread re-traps forever. The same C program without handlers exits 139. The Odin runner relies on such a handler (`stop_test_callback` in `core:testing`) to learn that a test failed. `kill` (SIGTERM) does not end the run, because the first SIGTERM only sets a flag in the runner; a second SIGTERM calls `os.exit`, and `kill -9` on the `tests` process works. Outside the sandbox this was not tried, so it is not confirmed that the runner works there. The orphaned `tests` processes from earlier sessions (12 h old) are probably the same hang. A fix would kill the whole process group from `build.sh`; `perl -e 'alarm N; exec ...'` only kills `odin test`, not its `tests` child.
- **`for x in m[k]` over a map index loops forever when `k` is missing (Odin dev-2026-09).** S16 grepped `src/`, `tests/` and `tools/` for ranges over an index expression and found no remaining site over a map (`importer_dirs` was already rewritten; `untyped_map` and `diagnostics` are enum-indexed arrays, and the rest index slices or fixed arrays). `lint_loops` reports the pattern. Candidate upstream Odin issue, not filed. Repro:

  ```odin
  package main

  main :: proc() {
  	m := make(map[string][dynamic]string)
  	for d in m["x"] { _ = d } // never ends
  	l := m["x"]
  	for d in l {} // ends
  }
  ```

## Whole-file resolve (`src/server/file_resolve.odin`)

- **Other `position_context` fields persist across nodes in the whole-file walker.** `parent_binary`, `index` (with `previous_index`) and `field_value` are set while walking one node and never restored, so a later sibling can read a stale value. They were not audited.
- **A failed overload resolution is cached for the rest of the file.** `resolve_function_overload` stores an empty result in `ast_context.call_expr_recursion_cache` before it expands the call arguments, and a failure leaves it there. Every later resolution of the same call returns that failure. The parameter-length `make` hang was one trigger and is fixed at its cause (parameters are now stored before body locals). Another failing argument still poisons the call.
- **The whole-file resolve now allocates its temp memory from the document cache arena.** This keeps the cached symbols valid after the request frees temp memory. It also retains the resolve scratch until the document is reparsed or caches are invalidated. Measured `symbol_cache_arena.total_used` after `resolve_entire_file`: 23.9 MB without the swap and 29.1 MB with it for a 100 KB file (+5.2 MB, +22%), and 57.7 MB and 70.5 MB for a 250 KB file (+12.9 MB, +22%). A targeted copy of the escaping data (`pkg` strings, docs, synthesized nodes such as `wrap_pointer`) would remove the extra share. It needs an audit of every default `context.temp_allocator` that a cached symbol can point to.

## Overload resolution and hover (`src/server/analysis.odin`, `src/server/hover.odin`)

- **Equal overload scores pick the first member.** `ab(T1, nil)` with `a :: proc($tag: Tag, p: []u8)` and `b :: proc($tag: Tag, p: ^int)` scores both members -2, so hover takes `a`. This is right when the results agree, as in `hover_overload_with_poly_constant_param`, and wrong when they differ.
- **The layout offset of a promoted field resolves the `using` type in the hover's package.** `promoted_field_offset` in `src/server/rols_layout.odin` calls `resolve_type_expression` on the `using` field's type without switching to the package that declares it. A `using` field of a type from another package may not resolve, and then the hover shows no offset.
- **The member of `offset_of` is recognized by the callee name.** `offset_of_member_arg` in `src/server/rols_offset_of.odin` treats any call named `offset_of` or `offset_of_member` with two arguments as the builtin. A user procedure that shadows either name loses resolution of its second argument. Hover and go-to-definition on the member still resolve it as an identifier, so they show a package or global of the same name. Only references and rename go through `resolve_location_offset_of_member`.
- **Whole-file resolution keeps overloads whose arity cannot fit the call.** File resolution runs with the `.Completion` hint, so `resolve_function_overload` skips the arity filter. When the only fitting member fails to resolve, the lone non-fitting member wins. `lint_calls` now skips its `argument-count` error when the resolved member has another name than the call and the written name declares a procedure group (`calls_proc_group`, which builds a fresh package `AstContext` per such call). Other readers of the file map still see the non-fitting member, and a wrong-arity call through a group is no longer reported.
- **`comp_lit_inside_call` compares source offsets.** `src/server/rols_resolve.odin` decides that an implicit selector belongs to a comp literal when the literal starts after the call. Only `references_enum_in_comp_lit_argument` covers it, with a typed literal as the first argument.

## Build tags and `when` (`src/server/build.odin`, `src/server/when.odin`)

- **Files excluded for the host are not indexed, so a call from an excluded file resolves to the host's sibling.** The open file's own declarations win, and the call-arity and struct-literal lints treat an excluded file like an inactive `when` branch. Navigation from such a file still goes to the wrong platform's declaration (for example `socket_linux.odin` on darwin reaches `errors_posix.odin`). A fix would index excluded files per target.
- **Only `lint_calls` and `lint_struct_literal` skip code in inactive `when` branches.** Other resolution-dependent lints still run there and can resolve names to the active branch's declarations. The same two lints, and the unused-declaration lint, also skip a target that only an inactive branch declares (a `Fallback` symbol).
- **A fallback symbol hidden by an active declaration does not come back when that declaration goes.** The index keeps one symbol per name: an active declaration replaces another file's fallback (`collect_symbols` in `src/server/collector.odin`). When a save or file removal drops the active declaration (`index_file` and `remove_index_file` in `src/server/build.odin`), the name stays absent until the fallback's own file is reindexed or the package is built again. Code in that inactive branch then resolves nothing, as before fallbacks existed. A fix would keep every candidate per name, or re-collect the package's other files when a removal empties a name.
- **Active code that names an inactive-only declaration resolves it.** Hover, definition and rename reach a `Fallback` symbol from code that the host builds, where odin reports `Undeclared name`. Completion does not offer it, and the call-arity, struct-literal and unused-declaration lints skip it. Two fallbacks of one name keep the first one indexed. With `when A { T :: struct { a: int } }` in one file and `when B { T :: struct { b: int } }` in another, code under `when B` in a third file can resolve `T` to the first file's declaration.
- **A `when` condition can read `pkg.NAME` only for a constant whose value folds to a bool, int or string.** Chains through other packages' constants and mutable globals are treated as unknown, which means false.
- **`#+build` project names are matched with an empty project name**, so a `#+build !name` line does not exclude anything.
- **Only rename and reorder-params change the platform variants of a declaration.** `declaration_variants` in `src/server/rols_variants.odin` finds them, but "Remove parameter", "Introduce parameter" and "Add ok result" call `find_call_sites` without variants and edit one declaration, so the other targets still break. `named_elsewhere` in `src/server/rols_action_lint_fix.odin` calls `proc_references` without variants, so it does not see a call that reaches another variant. Find references and the field rename of a per-platform struct also see one variant only.
- **The rename check sees a collision with `NEW` only in the files of the declaration and its variants and in the index.** A `NEW` declared in another file that the current target does not build, such as `other_windows.odin` next to the renamed `f_windows.odin`, is not reported, and the gate catches it only when it checks that target.
- **Variants are identified without evaluating `when` conditions.** Two declarations in different `when` statements of host-built files count as variants even when the conditions overlap, and two declarations in excluded files for the same target count as variants of the host's declaration. Both shapes are redeclarations that odin rejects on some target, so renaming them together is harmless, but such a duplicate is not reported.
- **`move_decl` compares the OS and architecture suffix of file names and the `#+build` lines literally.** Two spellings of the same constraint count as different, so the move is refused: `#+build linux, darwin` against `#+build darwin, linux`, or `#+build linux` against a `_linux.odin` name.
- **`move_decl` keeps a source import when any other identifier in the file is spelled like it.** `stale_imports` in `src/server/rols_move_decl.odin` counts names, not resolved uses, so a local `strings :: 1` elsewhere in the file keeps `import "core:strings"` after the only real user moves out. Resolving the remaining code with the declaration excluded would remove it.
- **`move_decl` adds every import the moved declaration spells to the target, even one a local shadows.** `used_imports` in `src/server/rols_move_decl.odin` matches selector names, so moving `show :: proc(strings: T) { _ = strings.f }` writes an unused `import "core:strings"` into the target. The test `move_decl_keeps_import_unused_before_the_move` records it.

## Poly call result symbols (`src/server/rols_edit.odin`, `src/server/analysis.odin`)

- **Poly resolution gives a call result the package of its type argument.** `size_buf := unwritten(b.buf)` with `unwritten :: proc(d: [dynamic]$E) -> []E` and `b: bytes.Buffer` resolves `size_buf` to a `[]byte` symbol whose package is `bytes`, not the document's. `symbol_type_text` guards against it at the consumer (a Variable or Constant symbol named like the variable takes the document package), so the add-explicit-type action and the inlay hints print `[]byte`. The root cause is still in the resolver, and any other consumer of `symbol.pkg` can see the wrong package. Hover on such a variable showed `c1.size_buf: []byte` in a quick check, so it is not visibly affected.
- **The proc-group case of `max(0, grp(a))` has no test that fails on the earlier `is_proc || is_group` check.** `get_proc_return_types` now takes the callee's return types when it has any, and otherwise keeps the call expression. Every group case tried (same package, other package, different arity) passed under both versions, so no group test was kept and the shape that broke is unknown.
