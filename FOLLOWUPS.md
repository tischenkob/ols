## Lints (`src/server/rols_lint*.odin`)

- Typed local constants such as `local : Cb : f` now produce a Variable semantic token and the Constant naming class in src/server/semantic_tokens.odin and src/server/rols_lint_naming.odin, matching typed globals, but no test covers either behavior for locals.
- The empty-body lint in src/server/rols_lint_no_op.odin still flags `for i := 0; i < n; advance(&state) {}`, whose post statement calls a procedure, although `for step() {}`, which calls a procedure in the condition, is exempt.
- `src/server/rols_lint.odin` has its own file-private `package_siblings` that compares `filepath.dir(file.fullpath) != filepath.dir(document.fullpath)` exactly, so on Windows a drive-letter case mismatch between the workspace walk and the document path drops siblings from the lints that use it (rols_lint.odin:967); switch it to `same_dir`/`same_path`.
- The multi-target lint in src/server/rols_lint.odin (`walk_lints`) also runs when a called name's only variants are for targets that do not build the file. Repro: `#+build linux` main.odin calls `h`, which b.odin (`#+build linux`) and a.odin (`#+build darwin`) both declare. The lint then walks linux_arm64, linux_i386 and linux_riscv64 for nothing. It could compare the variant files each target builds and skip the extra pass when they match.
- **`unused-parameter` builds the whole workspace import graph on each lint run that needs the importer scan**, adding about 70 ms per lint of `src/server/requests.odin` on this 565-file repo. Caching the graph across runs and clearing it on save or watched-file changes would remove that cost (`src/server/rols_lint.odin` `used_by_importers`, `src/server/rols_rename_package.odin` `import_graph`).
- **An `unused-parameter` verdict that depends on an importing package is not refreshed when that package changes**, because `relint_package_siblings` only relints files of the same package. Repro: open `a/a.odin`, then remove `register(a.handler)` from `b/b.odin`; the hint on `x` does not return until `a/a.odin` changes (`src/server/rols_lint_refresh.odin`).
- A change to a file of an importing package (open, or reported through didChangeWatchedFiles) never relints the open files of the imported package, although `used_by_importers` in `src/server/rols_lint.odin` reads importers for the unused-parameter verdict: with `a.odin` open in package `p` and `q/c.odin` importing `p`, adding `register(p.f)` to `q/c.odin` leaves `x` in `f` reported on `a.odin` until a file of `p` changes, because `relint_siblings` in `src/server/rols_lint_refresh.odin` only matches siblings in the changed file's directory.

## Safe-rename check (`src/server/rols_rename_check.odin`)

- **Deferred performance note: a field rename reads every workspace file once.** The check of a field rename reads the workspace once into memory, then parses only the files that name a carrying type and contain `using` or declare an alias of it, and the files with `#+feature using-stmt` or a `using v := value` declaration. Before stage S8 it read the workspace once for every type it searched. On a synthetic package of 201 files (200 name the owner type, an alias chain `A2 :: distinct A1`, `A1 :: Foo`, and 20 structs that embed `A2`), the dry-run `ols query rename` of a field went from 0.57 s to 0.21 to 0.25 s, and a refused rename with 20 causes went from 0.49 s to 0.15 s. On tina (`src/io_types.odin:287:2`) it stays at 0.28 s. A cached word index of the workspace would remove the reads, but it was measured on 2026-10-08 (follow-up E7) and not built. On this repository (489 files, 3.9 MB), a dry-run `ols query rename` of `Sibling_Values.scans` took 368 ms, about 215 ms above a hover. A warm index in the server would save about 30 to 40 ms of that, and it would keep 2 to 4 MB in memory and go stale for a file changed outside the editor when the client does not watch files. The CLI builds the workspace per process, so it would have to build the index (20 to 100 ms) inside the request and would get slower. Revisit only if a profile on a much larger workspace (tens of MB) shows the reads dominating a server request.
- **An inactive-branch test assumes a non-Linux host.** `tests/rols_rename_safe_test.odin:L2209` uses `else when ODIN_OS == .Linux` in an inactive-branch test, so on a Linux host that branch is active and the test may fail. Switch it to an OS that no CI host runs, such as `.Haiku`.
- **The rename-check files are not odinfmt-clean.** Running the current `./odinfmt -w` on `src/server/rols_rename_check.odin` and `tests/rols_rename_safe_test.odin` rewrites unrelated hunks (long string literals, `data`/`visit` alignment). The repository needs one formatting pass, or odinfmt needs a fix.
- **Deferred performance note: implementation requests on a procedure still read every workspace file.** `proc_group_locations` in `src/server/rols_implementation.odin` calls `find_symbol_references`, which reads each file and now parses only a file whose `proc{` group literal lists the procedure's name (`mentions_proc_group`). Stage S8 measured `ols query impl` at 0.24 s before and 0.13 s after on `get_token_range` in this repository, and 0.93 s before and 0.22 s after on `strings.index` in Odin's `core`. A cached word index of the workspace would remove the reads, but it was measured on 2026-10-08 (follow-up E7) and not built. `ols query impl` on `get_token_range` took 103 ms, about 40 ms above a hover. A warm index in the server would save about 15 to 20 ms of that, because the 53 files that name the procedure must still be read for `mentions_proc_group`, and it would keep 2 to 4 MB in memory. The CLI would get slower, as for the field rename. Revisit under the same condition as the field-rename note.
- **A file that no target builds loses its own collision check.** `check_collisions` in `src/server/rols_rename_check.odin`: when the renamed declaration sits in a file that no target builds (`#+build ignore` or a dot-prefixed name), a plain file-scope declaration of NEW in that same file is no longer reported, because `builds_together(self, self)` is false. Repro: `a.odin` with `#+build ignore`, `foo :: 1` and `bar :: 2`, then `ols query rename a.odin:2:1 bar` is not refused. This matters for `odin run file.odin -file` scripts.
- **odinfmt disagrees with the committed formatting of `src/server/rols_rename_check.odin`.** `./odinfmt -w` on that file realigns `data  =` in two `ast.Visitor` literals and rewraps two long string lines, so formatting the whole file produces churn unrelated to a change.
- `file_private_global` in src/server/rols_rename_check.odin calls `collect_globals(document.ast, open_file = true)` without an AstContext, so it evaluates file-scope `when` for the host in an excluded file. Repro: a name declared `@(private="file")` only in the target's branch of foo_windows.odin is not seen as file-private during the rename check on darwin.

## Rename, imports and lints from the mirage gaps (2026-10-07)

- **There is no cross-package move.** `move_edit` in `src/server/rols_move_decl.odin` refuses a target outside the declaration's directory, so moving `playtest.equal` to `framework:playtest/expect` means rewriting every call site by hand. A `move-package` engine in a plain `rols_` file, called by the CLI `move --to DIR/FILE.odin` and optionally by a code action, needs:
  - checks that the name is free in B, the procedure is not `@(private)`, its body uses nothing private to A, and B does not import A (no import cycle, via `graph_importers`);
  - a body rewrite: bare uses of A's globals get A's qualifier and an import of A, `B.x` loses its qualifier, and relative imports get a new path;
  - call sites from `proc_references` in `rols_change_signature.odin`: in A, bare `P` becomes `b.P` plus an import; in B, `a.P` becomes `P`; elsewhere, `a.P` becomes the file's alias of B or a new import. Each file then drops its import of A when nothing else uses it. Locals that capture the alias are checked as `check_import_name` does.
  - `import_edit`, `package_alias` and `package_import_path` in `rols_edit.odin` reworked to work on a `^Document` and a config instead of an `ActionContext`.

  Estimate: 500 to 700 lines of engine and 400 to 600 lines of tests, the size of `rename_package`.
- **Import path completion still offers gitignored directories.** `import "mirage:` lists `build` in mirage, because that completion lists the directories at the cursor and does not read the package aliases that `find_all_package_aliases` now filters.
- **The editor package rename drops the warnings of `rename_package`.** `rename_package_clause` in `src/server/rols_rename_package_clause.odin` discards them, so an editor user does not see a qualifier that did not resolve, an importer that failed to parse, or a file that the filter skipped. A fix needs a `window/showMessage` helper.
- **The package rename reads files from disk, including open documents with unsaved edits.** `package_sources` and the importer loop in `src/server/rols_rename_package.odin` read the disk, so an unsaved buffer that shifts lines gets edit ranges in the wrong place. A fix uses the open document's text when `document_get` finds it.
- **A `_test.odin` file in the renamed directory that imports its own package may keep `old.x`.** Its qualifiers resolve like a self-import and end as "cannot resolve" (see `tests/rols_rename_package_test.odin` around the self-import case). Unconfirmed whether Odin accepts that layout.
- **The package rename has not been applied in Zed or Helix.** Only raw stdio checked the edit, with the directory `RenameFile` last. Run one rename in each editor before relying on it. After the rename, the index keeps the old package path until it is rebuilt.
- **The refusal for a client without workspace folders has no harness test.** The harness always passes the main document as `files`, so only a stdio run reaches the check.
- **The package aliases do not refresh on a runtime change to the workspace filter.** `didChangeConfiguration` rebuilds them only when `enable_auto_import_skip_hidden_paths` changes, so a change to `workspace_exclude`, `workspace_include` or `enable_workspace_gitignore` waits for the next watched file create or delete. When one collection holds several workspace folders, only the first folder's filter applies.
- **`ignored-result` misses two cases that the compiler rejects.** It skips `f() or_return` when a result is left over, and a call in `defer`, though the compiler checks `@(require_results)` in both.
- **An import alias outside ASCII is not found at a qualifier.** `import_name_at` in `src/server/rols_rename_import.odin` finds the word under the cursor by bytes.
- **agent-lsp: `TestSpeculativeSessions/Go` fails on `main` before and after the `exclude_globs` fix.** All six subtests fail in the `test/` integration package, which `make test` does not run.
