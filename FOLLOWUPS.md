## Compile gate

- **`odin check` is sometimes killed by signal 11 with no output, so the gate reports "did not run" instead of rolling back.** Seen in Skald (58 packages, `ols query attr add skald/text.odin:L:1 deprecated=1 --apply` on a copy, which must roll back with exit 4): 6 of 40 runs, and 6 of 60 in another batch, failed the check before or after the write ("refused, nothing written" or "printed nothing after writing"). A debug print in `check` showed the failing process with `exit_code = 11`, about 10 ms of CPU and an empty buffer, for packages such as `examples/09_widgets` and `examples/48_audio`, so a different package each time. `record_check_run` in `src/server/rols_check_run.odin` reads this correctly: no output and a non-zero exit. The cause is the child, not the pipe read: 700 plain `odin check` runs of the same packages with 10 in parallel (a loop outside ols) did not fail, and the final drain read in `check` returns EOF, not an error. `core:os` `_process_wait` (`process_posix.odin:323-325`) stores the signal number in `exit_code` for a killed child, so `exit_code = 11` with no output is almost certainly SIGSEGV in the forked child or in `odin`. Unproven whether the child crashes in the fork before `execve` (`core:os` `process_start` runs non-async-signal-safe code there) or `odin` crashes at start. A bounded retry of a process that exits non-zero with no output would hide it, and the retry would not explain it. Next step: run the loop with a `posix_spawn`-based launcher or log the signal with `waitpid` to split the two.

## Edits (stage S9)

- **Organize imports still adds imports above the first import.** `organize_import_edits` in `action.odin` (upstream) does not use `import_group_offset`, which the code actions and modernize now share.
- **"Add explicit type" writes the variable name for a local declared with an inline aggregate type.** `p: struct { a: int }` followed by `x := p` becomes `x: p = p`. The symbol that `p` resolves to is named `p` and has no `.Anonymous` flag, so `symbol_type_text` in `rols_edit.odin` takes the name for a type. A field or element of an anonymous type (`s.inner`, `arr[0]`) is refused since the `.Anonymous` check in `symbol_type_text`. The flag is probably lost where a local's type expression is resolved in `analysis.odin` (upstream). Unverified for inlay hints and the other `symbol_type_text` callers.
- **The fill broadcast is withheld for element types where Odin may reject an untyped value.** `broadcasts` in `rols_lint_use_stdlib.odin` keeps `slice.fill` for matrix and enumerated-array elements and for `nil` into a union, even when the value is typed and a broadcast would compile.
- **The fill rewrite accepts a value that reads an element through a pointer field or a call.** `reads_array` in `rols_lint_use_stdlib.odin` refuses an index, slice or deref through a pointer, but not a field read through a pointer to an element: `p := &items[0]; for &e in items { e = Item{x = p.x * 2} }` is still offered, and the rewrite reads `p.x` once. A value that calls a procedure that reads the array escapes the check the same way.
- **A builtin `use-stdlib` target declared in another file of the package still captures the call.** `stdlib_matches` in `src/server/rols_lint_use_stdlib.odin` drops a builtin match (`max`, `min`, `abs`, `clamp`, `copy`) when `name_taken` finds the name in the open file, including the enclosing procedure and its locals. A package-level `max` declared in a sibling file is not seen, so the rewrite would call it. Closing it needs a lookup in the package index.

## Lints (`src/server/rols_lint*.odin`)

- **Dead-store matches a `defer` by name only.** `deferred_mention` in `src/server/rols_lint_dead_store.odin` keeps a store silent when a `return` or branch lies between it and the overwrite and a `defer` written earlier in the procedure mentions the name, even a `defer` in a block that has already closed or one that names a shadowed variable.
- **The `range-off-by-one` guard through a local length matches by name.** `names_len_local` in `src/server/rols_lint_loops.odin` accepts any earlier `n := len(x)` in the same top-level declaration, so a shadowing `n` or a later `n += 1` still counts as a guard. A length held in a parameter or a struct field is not seen. The guard check ignores the operator and the comparison direction, so `if b < len(x) || x[b] == 0` and `if b > len(x) { x[b] }` count as guarded. A use in the `if` init (`if v := x[b]; b < len(x)`) also counts as guarded.
- **`pure-call-unused` judges a pointer variable argument by name lists only.** `strings.to_reader`, `to_reader_at`, the `intern_` procs, `to_cstring` and the `*_iterator` procs are now exempt by name in `src/server/rols_lint_pure_call.odin`. Another pure-package procedure that writes through a pointer variable (not `&x`) still reports. A rule for any pointer-typed argument would also hide real pure calls, so each new case needs a per-proc judgement.
- **`PURE_PACKAGES` lists `/slices`, but the core package is `core:slice`.** `lint_pure_call` in `src/server/rols_lint_pure_call.odin` therefore never checks `slice.*` calls. Unverified whether this is deliberate.
- **A bare-bool or numeric constant is not named-checked.** `is_enabled :: true` is classified as an alias, so no naming rule applies. `count :: 5` still must be SCREAMING_SNAKE_CASE.
- **`make-len-append` recognises only a written `[dynamic]T`.** `make_len_append` in `src/server/rols_lint_allocator.odin` skips `Array :: [dynamic]int` followed by `make(Array, 4)` and `append`. The allocator-mismatch check now resolves a named type through `lint_symbols`; the same lookup would close this.
- **The ignored-result proc-type check and `compares_non_bool` build a fresh `AstContext` per hit.** `names_proc_type` in `src/server/rols_lint.odin` runs only for `Err`-named results, and `compares_non_bool` in `src/server/rols_simplify.odin` for comparisons with `true` or `false`. `LintContext` could carry the walker's context instead.
- **`bool-compare` reports an index or deref operand of a non-`bool` boolean type.** `compares_non_bool` in `src/server/rols_simplify.odin` judges identifiers, selectors and single-result calls only, so `return xs[i] == true` with `xs: []b32` is still reported, and dropping the comparison returns a `b32` where `bool` is expected. A comparison that is the condition of an `if`, a `for` or a ternary is reported whatever the operand, because a condition accepts any boolean type.
- **`redundant-type-assertion` only matches a plain identifier subject.** `switch _ in x.shape { case Circle: c := &x.shape.(Circle) }` is not reported. `match_switch_binding` in `src/server/rols_lint_redundant_type_assertion.odin` proves the subject by name, so a selector subject also needs a check that no part of the chain is written in the clause.
- **`unused-parameter` sees value uses of a procedure only in its own file.** `value_names` in `rols_lint.odin` walks the open file once. A handler that another file of the package registers still reports. Closing the gap needs a scan of the package's indexed files, so the lint would pay that cost for each file it checks. A same-named local that resolves to a procedure also counts as a use, and a mention that resolves to a variable does not.
- **The `unused-parameter` rename fix does not see a call through a procedure group in a file that does not reference the procedure.** `param_named_elsewhere` in `src/server/rols_action_lint_fix.odin` searches the references of the procedure and its platform variants, for the quick fix and for `ols query modernize`. A call `g(x = 1)` through a group `g :: proc{f, …}` declared in a file that never names `f` is not found, so renaming `x` to `_` breaks it; the CLI compile gate catches it and rolls back.
- **`ols query modernize --rule unused-parameter` runs a workspace reference search per fix and pass.** `modernize_fixes` in `src/server/rols_modernize.odin` calls `param_named_elsewhere` for each unused parameter of a top-level procedure, which reads every workspace file that names the procedure. On a large workspace with many unused parameters the run may be slow; this was not measured. From the second pass on, the document holds the rewritten text while other files still resolve the procedure through the index built from the original text, so when an earlier fix shifted the procedure's name, `proc_references` misses the calls in other files and a breaking rename can go through; the CLI compile gate catches it and rolls back.
- **The multi-value expansion counts a group call by the members the whole-file resolve kept.** `arg_results` in `src/server/rols_lint_printf.odin` (shared by the printf and argument-count lints) uses the result count when every kept member agrees, and skips the count checks of the call otherwise. Because the resolve skips the arity filter, it can keep one member that does not fit the call, and then that member's count is used. A callee that does not resolve, or a group that only resolves without the call, is resolved again in a fresh package `AstContext` per argument (`group_results`), so a local that shadows a global group reads as the global.
- **The multi-value expansion counts any callee that is not a name as one value.** `arg_results` in `src/server/rols_lint_printf.odin` counts a conversion such as `(^int)(p)` correctly, but also counts `(f)()`, `f()()` and `arr[i]()` as one value although their result count is unknown. The resolve map holds named callees only. This predates the group counting.
- **printf does not consume an argument for an unknown verb.** core:fmt reads the argument for `%k` and prints `%!k(…)`, while `consume_verb` in `src/server/rols_lint_printf.odin` reports the verb and leaves the argument unread. `fmt.printf("%k", x)` therefore also reports `x` as an extra argument.
- **Enum switch coverage treats a member value it cannot evaluate as distinct.** `enum_member_values` in `src/server/rols_layout.odin` (shared by `redundant-partial` and the populate-switch-cases action) evaluates integer constants in the enum's package and folds expressions over earlier members, such as `LAST = C + 0`. A value it cannot evaluate, such as a constant that does not resolve or an operator `const_int` does not fold, gets its own case, so the action may still emit a duplicate for it. A constant that resolves to the wrong declaration gives a wrong value, which can merge two members or split an alias from its target; `const_int` relies on `resolve_type_expression` to find the declaration.
- **Unused imports count a package named in either branch of a `when` as used.** `odin check` checks only the taken branch, so it reports `core:hash` in `internal/engine/unload.odin` of the sweep project when every `hash.` sits under a false `when hostabi.CHECKED`. `find_unused_imports` in `src/server/imports.odin` walks both branches on purpose, because organize-imports on save would otherwise delete an import that another build configuration needs.

- **The nested-if merge refuses every named callee it cannot resolve.** `callee_deferred` in `src/server/rols_action_split_merge_if.odin` counts a callee as deferred when neither the whole-file resolve map nor a package-level resolve finds it, and a group call whose overload does not resolve as deferred when any member has a `deferred_*` attribute. A procedure group declared inside a procedure body, or a callee the resolver misses, therefore refuses the merge although the call may be harmless.

- **Field renames still read every workspace file.** `check_embedders` passes `require_text = "using"` to `find_symbol_references`, so a file is parsed only when it mentions both the owner type and `using`. The search still reads every file to test that. On 200 files that mention the type, the dry-run `ols query rename` of a field took 0.50 s before and 0.33 s after. ## Edits (stage S10)

- **"Add ok result" refuses every caller shape it cannot extend.** It adds `, _` to `v := f()`, `v = f()`, `a, b := f()` and the `if` init form, leaves a statement call alone, and refuses the whole action for a call used as an argument, a return value, an `or_return` operand, a typed declaration, a named-argument call and a procedure used as a value. `#optional_ok` would keep most of those compiling but changes the result type the tests expect. A local procedure is refused when its name appears anywhere else in the file.
- **"Add defer <free>" trusts every statement call except the append family not to keep its argument.** `escapes_from` in `src/server/rols_action_defer_delete.odin` refuses when the variable, or a value derived from it, is returned, stored, used as a map key, reassigned or passed to a call whose result is kept. A call such as `register(&list, s)` whose result is discarded may still store `s`. Only `append`, `append_elem`, `append_elems`, `inject_at`, `assign_at` and `map_insert` are known to store an argument. The walk is also conservative: `y := p.x` and `n := f(s)` refuse the action even when the copy shares nothing.
- **"Add defer <free>" follows only a top-level `for &e in s` alias.** `escapes_from` in `src/server/rols_action_defer_delete.odin` follows `e` when the loop ranges over the variable itself. A loop over an element, as in `for &e in s[0] { g = &e }`, or a nested `for &f in e` alias is not tracked, so the pointer it stores into `s` goes unnoticed.
- **"Add ok result" does not look past the workspace.** `find_call_sites` reads the workspace files, so a caller in a package outside the workspace folders still breaks.
- **"Unwrap block" refuses when `enclosing_stmts` finds no statement list,** such as an `if` in an `else if` chain. `ends_flow` in `src/server/rols_action_unwrap.odin` treats any call of a selector named `exit`, such as `os.exit(1)` or `app.exit()`, as the end of the flow, so a method named `exit` that returns also refuses the action.
- **"Inline procedure call" refuses on any identifier match into another file.** `borrows_from_file` in `src/server/rols_action_inline_proc.odin` checks both directions. Toward the caller it is scope-aware: a name the copy takes from outside the callee refuses only when a local visible at the call, a file-private declaration of the caller's file or an import of another package binds it there. Toward the callee's file it does not track shadowing, so a parameter or local named like a file-private declaration or an import of the callee's file refuses the action. It does not add the missing import for the caller.
- **"Inline variable" refuses more than it must to keep evaluation order.** An initializer moved past a statement must hold no call (builtins such as `len` included), no index, slice or deref, no `context`, no selector on a variable or parameter, no global read and no name the resolver misses (`reads_state` in `src/server/rols_action_inline_variable.odin`). An initializer that fails this is inlined only into the next statement, where nothing before the use may call or read any variable other than a plain local `=` or `:=` target (`evaluated_in_place`). So `v := f(); g(a, v)` is refused for a local `a`, `v := bump(); counter = v` is refused because `counter` is a global target, and `n := len(s)` across a statement is refused. A literal initializer with more than one use is refused, as is a read of a `using` field. A purity table for builtins and a type check for value-typed locals would widen it. An unresolved callee name such as `bar` in `bar(v)` is still accepted, because compiling code can only call a procedure there.
- **"Generate test" refuses a result whose zero value needs a package-qualified type.** `result_checks` in `src/server/rols_action_generate_test.odin` spells an aggregate as `T{}` because `testing.expect_value` cannot infer a bare `{}`. For `time.Time` the test file would need the import, so the action is withheld instead. The action is also withheld for a result that `testing.expect_value` rejects as not comparable, such as `any`, a struct holding a slice, a `#raw_union` struct, a `#soa` fixed array or a fixed-capacity dynamic array; a field assertion per member would lift it.
- **"Generate test" deletes every slice, dynamic array and map result.** The stub writes `defer delete(result)` and `testing.expect(t, len(result) == 0)`. A procedure that returns a view into memory it does not own, such as a sub-slice of a global, gets a test that frees memory it must not free; the author edits the stub.
- **`rename-package` rewrites a bare package name only as the value of a declaration.** `alias :: old` is rewritten. Any other bare use of the name is left alone because it may be a field or a local.
- **"Add ok result" refuses any procedure with `or_return`**, because `or_return` assigns the operand's end value to the last result and Odin rejects `Err` to `bool`.
- **`builtin_without_decl` counts a constant named like a builtin type as a type.** `builtin_without_decl` in `src/server/rols_edit.odin` qualifies a builtin type name only when the package declares that name as a type outside a file-private scope. A constant such as `string :: "x"` is indexed as `.Unresolved`, like a distinct type, so it still counts, and a builtin `string` result prints as `pkg.string`, which does not compile. Telling the two apart needs the declaration's value kind in the index.
- **`declares_inside` misses a range value taken by reference.** `declares_inside` in `src/server/rols_modernize.odin` matches only plain identifiers among a `for` loop's values, so `name_taken` does not see `for &fmt in xs` as taking the name `fmt`. Unwrapping the `&` there would close it.
- **The ok-flag check resolves a callee's result type with the open file's imports.** `result_kind_in` in `src/server/rols_action_result_handling.odin` resolves `pkg.My_Ok` through `resolve_type_in_package`, which reads the imports of the open document. A selector type whose import name differs between the callee's file and the caller's file can stay `.Other`, or resolve to an unrelated boolean type of the same name and wrongly become `.Bool`.
- **"Inline procedure call" reads an untyped or unresolved literal as a struct literal.** `is_field_name` in `src/server/rols_action_inline_proc.odin` treats `K` in `{K = 1}` as a field name when the literal has no written type or its named type does not resolve, so a map or array key there is skipped by the capture check. Resolving the expected type of an untyped literal would close it.
- **"Remove redundant else" before more statements refuses on any mention of an else declaration.** `redundant_else` in `src/server/rols_simplify.odin` refuses when any other statement of the block names a variable that the else declares, including as a field name such as `p.y`. It also refuses when the else ends in a `return` or branch, since the statements after the `if` are already unreachable.

## CLI queries (`src/cli/rols_cli.odin`, `src/server/rols_find.odin`)

- **`check` and `tests` in a directory without `.odin` files cover every package of the root, with one `odin check` per package.** The run gets the 20 s of an editor check for each batch of cores packages, capped at 10 minutes (`gate_check_timeout`), and the packages share no cache, so a large repository takes long.
- **`find` parses every workspace `.odin` file on each call.** The LSP workspace symbols read the index, which parses each package once. `find_symbols` reads all files again, so a call on a large tree such as Odin's `core/` costs one parse of the tree. A cache across calls does not help a one-shot CLI process.
- **`tests FILE` drops a file that the target does not build.** `odin test -file` may still build a file with `#+build` tags that exclude the host; this was not checked.
- **`find` and `tests` evaluate `when` for the editor's target, not the CLI's.** `inactive_when_decls` in `src/server/rols_when_inactive.odin` evaluates `ODIN_OS` and `ODIN_ARCH` from the profile, else the host, as the editor does, while the whole-file `(other platform)` mark and the file filter of `find_tests` use the `-target:` of `checker_args`. With a `-target:` in `checker_args`, a `when ODIN_OS == …` branch is judged for the host. Seeding the `when` map from `base_target` in the CLI would align them.
- **`find` and `tests` treat a `when` condition with a selector or another file's constant as unknown.** `when_known` accepts `ODIN_OS`, `ODIN_ARCH`, profile defines, literals, `#config` and the constants of the same file outside any `when`. `pkg.FLAG`, a constant from another file of the package, and builtins such as `ODIN_DEBUG` leave the branch unmarked, even where the editor's index evaluates `pkg.FLAG`.
- **`lint` drops the diagnostics of a file that does not parse.** It notes the file as skipped on stderr and leaves out the per-file lints that the server still runs on the partial tree, so `--fail-on` no longer sees a code reported only there. `check` keeps those lints, since `odin check` reports the syntax error itself.
- **`check DIR` still runs `odin check` over the gitignored files of `DIR`.** Only the lints follow the workspace filter; odin checks every file of the package, so an error in a gitignored file is reported.
- **A gitignored `DIR` named on the command line loses its subdirectories.** `package_dirs_below` in `src/server/rols_find.odin` keeps the named directory but skips each subdirectory that the filter skips, and below an ignored directory every subdirectory is ignored too, so `lint build/` lints only `build/` itself.
- **`lint DIR` runs `git ls-files` once more than it needs.** `package_dirs_below` in `src/server/rols_find.odin` builds its own workspace filter for each `DIR`, and `collect_lints` in `src/cli/rols_cli.odin` builds `lint_filter` once more, each calling `collect_git_ignored`. Passing one filter to both would save the second call.

## CLI compile gate (`src/cli/rols_apply.odin` `run_edit`)

- **The gate checks only the targets that touched files and target-less importer directories need.** A sibling file that the host excludes, such as `lib_windows.odin` next to an edited `lib.odin`, and the excluded files of an importer directory that also has a host file are not checked on their targets. A break there passes the gate unless `checker_targets` names the target.
- **Every extra target checks every package.** `gate_targets` in `src/cli/rols_gate.odin` returns one list, so a `_windows.odin` edit in a workspace with many importers runs all packages again for `windows_amd64`. Checking only the importers of the packages that need the target would cost less.
- **An extra target drops a package only for an error outside the workspace.** `gate_baseline` in `src/cli/rols_gate.odin` skips a package on an extra target when its baseline check there names a file outside the workspace. A package that does not build on that target but whose errors are all in workspace files stays gated, and its error set can still change between runs. A package that does build there but already reports an error inside a core generic loses its gate on that target. Dropping a package costs a second baseline run of that target.
- **The rename rewrite uses lines, not columns.** `on_edited_line` in `src/cli/rols_gate.odin` lets a before error on a line the rename edits match the renamed form. An unrelated error on the same line still can. An error whose position is on another line of a multi-line call is not rewritten.
- **A genuine Syntax Error pays for the style rerun.** `check` in `src/server/check.odin` reruns a package without the style flags whenever a run with them reports a Syntax Error, so a file with a real syntax error is always checked twice, and the whole run gets `2 * timeout` (not one extra per rerun). The reruns never exceed `max_concurrent_checks`: only a process that just finished queues one, so the running processes and the pending reruns together stay within the cap.

## Large-file performance (stage S15)

- **Opening a 2 MB file still takes 1.3 to 2.4 s.** On `core/rexcode/isa/ppc/mnemonic_builders.odin` (13,308 declarations), `didOpen` spends about 0.3 s parsing and about 2 s in `resolve_entire_file` for the lints. The stacks show no single hot spot: `clone_node`, `resolve_function_overload`, `create_uri` and `store_local` each hold a few percent. ## Test harness (`build.sh`)

- **A test that panics or faults can hang in some agent sandboxes (found in S16).** There the fault handler that the Odin runner relies on (`stop_test_callback` in `core:testing`) is not reached, and the faulting thread re-traps forever: `invert_if_early_exit_do_body` at `c5c8fa27^` panicked on a bounds check and then spun, and a C program with `SIGSEGV` and `SIGTRAP` handlers behaved the same. This is an environment issue, not a rols bug. On 2026-10-06 a scratch test with `panic("boom")` failed normally in about 0.1 ms, so not every session is affected. `ROLS_TEST_TIMEOUT=SECONDS ./build.sh test` (or `single_test`) now bounds a hang: on timeout it sends SIGKILL to the process group of `odin test`, its `tests` child included, and exits 1. Set it lower than any outer timeout (GNU `timeout`, a CI cancel, an agent tool limit): an outer kill of the `build.sh` process group does not reach the test group. Without the variable a hang still never ends, and a plain `kill` of the run does not stop it, because the runner's first SIGTERM only sets a flag. `kill -9` on the `tests` process does stop it.
- **`for x in m[k]` over a map index loops forever when `k` is missing (Odin dev-2026-09).** S16 grepped `src/`, `tests/` and `tools/` for ranges over an index expression and found no remaining site over a map (`importer_dirs` was already rewritten; `untyped_map` and `diagnostics` are enum-indexed arrays, and the rest index slices or fixed arrays). `lint_loops` reports the pattern. Candidate upstream Odin issue, not filed. Repro:

  ```odin
  package main

  main :: proc() {
  	m := make(map[string][dynamic]string)
  	for d in m["x"] { _ = d } // never ends
  	l := m["x"]
  	for d in l {} // ends
  }
  ```

## Whole-file resolve (`src/server/file_resolve.odin`)

- **A failed overload resolution is cached for the rest of its declaration.** `resolve_function_overload` keeps a failed result in `ast_context.call_expr_recursion_cache`, which the whole-file walker clears between top-level declarations. Every later resolution of the same call inside that declaration returns the failure, even where it would resolve.
- **The binary walker leaves `binary` on the last nested expression it popped.** `resolve_binary_expr` pushes both operands and pops the right one first, so in `.X == a + b` the implicit selector `.X` is resolved with `binary` set to `a + b`. `resolve_implicit_selector` then finds the cursor outside that expression, and `.X` does not resolve, so references of `X` miss it. `a + b == .X` resolves.
- **The whole-file resolve now allocates its temp memory from the document cache arena.** This keeps the cached symbols valid after the request frees temp memory. It also retains the resolve scratch until the document is reparsed or caches are invalidated. Measured `symbol_cache_arena.total_used` after `resolve_entire_file`: 23.9 MB without the swap and 29.1 MB with it for a 100 KB file (+5.2 MB, +22%), and 57.7 MB and 70.5 MB for a 250 KB file (+12.9 MB, +22%). A targeted copy of the escaping data (`pkg` strings, docs, synthesized nodes such as `wrap_pointer`) would remove the extra share. It needs an audit of every default `context.temp_allocator` that a cached symbol can point to.

## Overload resolution and hover (`src/server/analysis.odin`, `src/server/hover.odin`)

- **Equal overload scores pick the first member.** `ab(T1, nil)` with `a :: proc($tag: Tag, p: []u8)` and `b :: proc($tag: Tag, p: ^int)` scores both members -2, so hover takes `a`. This is right when the results agree, as in `hover_overload_with_poly_constant_param`, and wrong when they differ.
- **The member of `offset_of` is recognized by the callee name.** `offset_of_member_arg` in `src/server/rols_offset_of.odin` treats any call named `offset_of` or `offset_of_member` with two arguments as the builtin. A user procedure that shadows either name loses resolution of its second argument in references, rename, hover and go-to-definition.
- **Whole-file resolution keeps overloads whose arity cannot fit the call.** File resolution runs with the `.Completion` hint, so `resolve_function_overload` skips the arity filter. When the only fitting member fails to resolve, the lone non-fitting member wins, and `lint_calls` reports an `argument-count` error against it. The `offset_of` package-name case was this shape. It is fixed at its cause, but any other resolution failure of the fitting member reproduces the false error.
- **A local hides a global in the initializer of another global.** Inside `use :: proc() { a: string; _ = G.x }`, the initializer of a later global `G := g(a)` resolves `a` to the local, not to the global. The likely cause is `get_local` in `src/server/locals.odin`, which checks the file, package and offset of a local but not whether the expression being resolved lies in the local's scope. The call fails to resolve there, and `G.x` in that procedure is unresolved. `file_resolve_failed_overload_is_not_cached` relies on this to make the call fail in one scope.

## Build tags and `when` (`src/server/build.odin`, `src/server/when.odin`)

- **Files excluded for the host are not indexed, so a call from an excluded file resolves to the host's sibling.** The open file's own declarations win, and the lints treat an excluded file like an inactive `when` branch: the lints in `resolving_lints` (`src/server/rols_lint.odin`), such as ignored-result, printf and call-arity, report nothing in such a file, for example `foo_windows.odin` on darwin. The test `resolving_lints_skip_file_the_host_does_not_build` pins it. Navigation from such a file still goes to the wrong platform's declaration (for example `socket_linux.odin` on darwin reaches `errors_posix.odin`). A fix would index excluded files per target.
- **The naming, deprecated and unused-parameter lints, and the use-stdlib hints, still resolve names in inactive `when` branches.** `resolving_lints` in `src/server/rols_lint.odin` leaves the three lints running there because their tests expect reports in such branches and they resolve only a kind, an attribute, or a procedure passed as a value. They see fallback symbols there, which is right for a name that only that platform declares. The use-stdlib hints (`src/server/rols_lint_use_stdlib.odin`) run outside the lint walker, so they see inactive code and fallbacks with no check at all. A platform variant with a different kind or deprecation, or a same-named variable, can still give them a wrong answer in that code.
- **In active code a name that resolves to a fallback reads as unresolved in the lints.** `lint_symbols` drops such nodes, and some lints treat a missing node as a local or a constant: `is_local_store` in `src/server/rols_lint_dead_store.odin` treats it as a local, and `is_constant_expr` in `src/server/rols_lint_bool.odin` as a constant. Active code reaches a fallback only when odin would report `Undeclared name`, or when the `when` evaluator misjudges a condition as false, so the lints can then report on the wrong assumption.
- **Active code that names an inactive-only declaration resolves it.** Hover, definition and rename reach a `Fallback` symbol from code that the host builds, where odin reports `Undeclared name`. Completion does not offer it, and in active code the lints skip it (`lint_symbols` and the unused-declaration lint). Two fallbacks of one name keep the first one indexed. With `when A { T :: struct { a: int } }` in one file and `when B { T :: struct { b: int } }` in another, code under `when B` in a third file can resolve `T` to the first file's declaration.
- **A `when` condition reads `pkg.NAME` through constants of that package only.** `fold_package_when_const` in `src/server/rols_when.odin` folds names in the value through constants of the same package. A selector, which reads a third package, is unknown: as the whole value it makes the condition false, and inside a named constant it makes that name read as false, so with `ON :: !MID` and `MID :: other.X` the constant `ON` folds to true. A mutable global and a cycle of constants also read as false.
- **`#+build` project names are matched with an empty project name**, so a `#+build !name` line does not exclude anything. A positive `#+build name` line reads as built nowhere: `builds_together` in `src/server/rols_check_targets.odin` then drops such a sibling from the rename collision scan, so a `NEW` declared there is not reported.
- **The field rename of a per-platform struct changes one variant only.** `declaration_variants` in `src/server/rols_variants.odin` serves rename, reorder-params, find references and the `unused-parameter` fix, but a field rename resolves the field through one struct declaration, so the same field of the struct's other platform variants keeps its name. "Remove parameter", "Introduce parameter" and "Add ok result" are withheld for a procedure with variants rather than changing them all.
- **The rename collision scan of sibling files reads file build tags and names only.** `check_collisions` in `src/server/rols_rename_check.odin` reports `NEW` in a sibling that some OS and architecture builds together with the declaration or a variant (`builds_together` in `src/server/rols_check_targets.odin`), and drops an index hit in a file that never builds with them. `when` conditions are not evaluated, so a `NEW` under `when ODIN_OS == .Linux` in a generic file still blocks renaming a declaration of `f_windows.odin`.
- **Variants are identified without evaluating `when` conditions.** Two declarations in different `when` statements of host-built files count as variants even when the conditions overlap, and two declarations in excluded files for the same target count as variants of the host's declaration. Both shapes are redeclarations that odin rejects on some target, so renaming them together is harmless, but such a duplicate is not reported.
- **`move_decl` matches imports by the selector base, not by resolution.** `stale_imports` in `src/server/rols_move_decl.odin` counts `strings.f` on a local `strings` elsewhere in the file as a use, so the import stays after its only real user moves out. `used_imports` skips a base that the moved procedure declares anywhere inside it, so a struct field or a local of another block spelled like the import also drops the import from the target. Resolving each base to a `.Package` symbol would fix both.
- **`move_decl` still compares `#+build` project names literally.** Two spellings of one project-name constraint count as different, so the move is refused.

## Poly call result symbols (`src/server/rols_edit.odin`, `src/server/analysis.odin`)

- **Poly resolution gives a call result the package of its type argument.** `size_buf := unwritten(b.buf)` with `unwritten :: proc(d: [dynamic]$E) -> []E` and `b: bytes.Buffer` resolves `size_buf` to a `[]byte` symbol whose package is `bytes`, not the document's. `symbol_type_text` guards against it at the consumer (a Variable or Constant symbol named like the variable takes the document package), so the add-explicit-type action and the inlay hints print `[]byte`. The root cause is still in the resolver, and any other consumer of `symbol.pkg` can see the wrong package. Hover on such a variable showed `c1.size_buf: []byte` in a quick check, so it is not visibly affected.
- **The proc-group case of `max(0, grp(a))` has no test that fails on the earlier `is_proc || is_group` check.** `get_proc_return_types` now takes the callee's return types when it has any, and otherwise keeps the call expression. Every group case tried (same package, other package, different arity) passed under both versions, so no group test was kept and the shape that broke is unknown.
