# Follow-ups

Known gaps and out-of-scope issues found during fork work. Each entry names where the issue is and a case that shows it. Remove an entry when its fix lands.

## Corpus validation (`docs/corpus-validation.md`)

- **Formatter gaps from the 2026-10-04 rerun.** Stage S19 fixed that rerun's formatter bugs, and the 2026-10-05 and 2026-10-06 reruns found no formatter failure in any project. Formatter gaps remain: a `;`-joined `case` body statement is never wrapped (see the doc's Follow-ups). A one-line `if x {a(); b()} else {c(); d()}` where only the `else` part overflows opens the `else` block and keeps `if x {a(); b()} else {` on one line (repro: `core/rexcode/isa/arm32/tools/verify_against_llvm.odin:581` in the Odin `core` collection). A `//` group directly followed by `/* b */ x: int` forms one comment group, so `/* b */` still moves above the field. A block comment before the first field of a struct or the first argument of a call still prints with a leading space and none after it (`\t /* a */` above `x: int` in a struct, `\t /* a */x,` in a broken call), and the struct case is not idempotent: the second pass drops the space. `visit_comment` in `src/odin/printer/visit.odin` treats a block comment on the line of the source position as trailing. A block comment before a later parameter or argument (`x: int, /* b */ y: int`) moves to its own line above it.
- **The doc's follow-ups have no passing harness test and each names a repro.** `docs/corpus/triage/` holds the reduced source of every confirmed case from the first sweep, and `python3 docs/corpus/triage/cli.py` reruns the CLI cases.

## Compile gate

- **The cause of the signal 11 crashes of `odin check` is unknown.** In Skald (58 packages, `ols query attr add skald/text.odin:L:1 deprecated=1 --apply` on a copy), 6 of 40 gated runs once failed with a check that exited by signal 11 after about 10 ms with no output, a different package each time, while 700 plain `odin check` runs outside ols did not fail. `check` in `src/server/check.odin` now reads the signal with `waitid` before reaping, logs it with the package, and runs that package once more, so the gate no longer refuses on one crash. Unproven whether the child crashes in the fork before `execve` (`core:os` `process_start` runs non-async-signal-safe code there) or `odin` crashes at start. Next step: count the logged crashes over a Skald loop, then try a `posix_spawn`-based launcher.

- **Organize imports still adds imports above the first import.** `organize_import_edits` in `action.odin` (upstream) does not use `import_group_offset`, which the code actions and modernize now share.
- **"Add explicit type" writes the variable name for a local declared with an inline aggregate type.** `p: struct { a: int }` followed by `x := p` becomes `x: p = p`. A value with a call is already refused by the pattern matcher.

## Lints (`src/server/rols_lint*.odin`)

- **Known limit: the `range-off-by-one` guard does not see a length held in a parameter or a struct field.** `guarded_by_len` in `src/server/rols_lint_loops.odin` accepts `len(x)` or a local `n := len(x)`, so `if b < count { x[b] }` with `count` a parameter or `if b < s.len { x[b] }` still reports. `names_len_local` refuses a local when any assignment in the top-level declaration targets its name, even one to another variable of that name, or when an assignment after it targets the collection. That match compares the text of the assignment target with the collection, so an assignment to a base of the collection is missed: with the collection `s.items`, `s = t` leaves the length counted as current. A change of the collection through a pointer, such as `pop(&x)`, is not seen, so the stale length still counts as a guard.
- **Known limit: `pure-call-unused` skips every procedure with a pointer parameter.** `has_pointer_param` in `src/server/rols_lint_pure_call.odin` treats a `^T` or `[^]T` parameter as an output, so a pure procedure that only reads through a pointer is skipped unless `ACCESSOR_NAMES` lists it. Since `core:slice` is checked, a discarded `slice.unique`, `unique_proc` or `bitset_to_enum_slice_with_buffer` result reports. These procedures change their argument in place, but only the result carries the new length, so the report is a true positive.
- **The scope checks of `dead-store` and `range-off-by-one` do not follow `using`.** `visible_declaration` in `src/server/rols_lint_scope.odin` finds the declaration of a name on the syntax tree, because the whole-file resolve gives a local no declaration range. A field that `using` brings into scope under the same name is not seen as a declaration, so a `defer` that names it, or a length guard through it, is matched to an outer local of that name.
- **The `naming` exemption for C names is per file.** `check_c_name` in `src/server/rols_lint_naming.odin` skips type, field, enum member and constant names only in a file that holds a `foreign import`. A binding package that declares `foreign import` in one file and its C types in another still reports the types.
- **The ignored-result proc-type check and `compares_non_bool` build a fresh `AstContext` per hit.** `names_proc_type` in `src/server/rols_lint.odin` runs only for `Err`-named results, and `compares_non_bool` in `src/server/rols_simplify.odin` for comparisons with `true` or `false`. `LintContext` could carry the walker's context instead.
- **`bool-compare` reports an index or deref operand of a non-`bool` boolean type.** `compares_non_bool` in `src/server/rols_simplify.odin` judges identifiers, selectors and single-result calls only, so `return xs[i] == true` with `xs: []b32` is still reported, and dropping the comparison returns a `b32` where `bool` is expected. A comparison that is the condition of an `if`, a `for` or a ternary is reported whatever the operand, because a condition accepts any boolean type.
- **`redundant-type-assertion` only matches a plain identifier subject.** `switch _ in x.shape { case Circle: c := &x.shape.(Circle) }` is not reported. `match_switch_binding` in `src/server/rols_lint_redundant_type_assertion.odin` proves the subject by name, so a selector subject also needs a check that no part of the chain is written in the clause.
- **`unused-parameter` sees value uses of a procedure only in its own file.** `value_names` in `rols_lint.odin` walks the open file once. A handler that another file of the package registers still reports. Closing the gap needs a scan of the package's indexed files, so the lint would pay that cost for each file it checks. A same-named local that resolves to a procedure also counts as a use, and a mention that resolves to a variable does not.
- **The `unused-parameter` rename fix does not see a call through a procedure group in a file that does not reference the procedure.** `param_named_elsewhere` in `src/server/rols_action_lint_fix.odin` searches the references of the procedure and its platform variants, for the quick fix and for `ols query modernize`. A call `g(x = 1)` through a group `g :: proc{f, …}` declared in a file that never names `f` is not found, so renaming `x` to `_` breaks it; the CLI compile gate catches it and rolls back.
- **`ols query modernize --rule unused-parameter` runs a workspace reference search per fix and pass.** `modernize_fixes` in `src/server/rols_modernize.odin` calls `param_named_elsewhere` for each unused parameter of a top-level procedure, which reads every workspace file that names the procedure. On a large workspace with many unused parameters the run may be slow; this was not measured. From the second pass on, the document holds the rewritten text while other files still resolve the procedure through the index built from the original text, so when an earlier fix shifted the procedure's name, `proc_references` misses the calls in other files and a breaking rename can go through; the CLI compile gate catches it and rolls back.
- **The multi-value expansion counts a group call by the members the whole-file resolve kept.** `arg_results` in `src/server/rols_lint_printf.odin` (shared by the printf and argument-count lints) uses the result count when every kept member agrees, and skips the count checks of the call otherwise. Overload resolution drops a member that takes fewer arguments than the call passes, but keeps one that needs more, so when the fitting member fails to resolve, that member's count is used. A callee that does not resolve, or a group that only resolves without the call, is resolved again per argument with the locals visible at the callee (`callee_results`), which walks the file to the callee each time.
- **The multi-value expansion counts `x->f()` as one value, and skips the count checks for an unnamed callee that is not a procedure.** A `Selector_Call_Expr` argument such as `fmt.printf("%d %d", x->pair())` counts as one value whatever `pair` returns. A conversion such as `(^int)(p)` and a directive such as `#location()` count as one value. A callee that can yield a procedure, such as `f()()`, `arr[i]()` or `p^()`, is resolved again, and when it resolves to neither a procedure nor a group, its count is unknown and the call's count checks are skipped.
- **Known limit: enum switch coverage treats a member value it cannot evaluate as distinct.** `enum_member_values` in `src/server/rols_layout.odin` (shared by `redundant-partial` and the populate-switch-cases action) folds integer and rune literals, the arithmetic, shift and bitwise binary operators, earlier members and constants declared as such expressions (in their own package) through `const_int`. A value it cannot evaluate gets its own case, so the action may still emit a duplicate for it: a call such as `size_of(T)` or `len(ARR)`, a conversion such as `u8(3)`, a unary `~` (its result depends on the type's width), a ternary, or a constant that does not resolve. `const_int` folds in 64-bit `int`, while Odin folds untyped constants at full precision, so a value that overflows 64 bits differs, and a shift by 64 or more is not folded. A constant that resolves to the wrong declaration gives a wrong value, which can merge two members or split an alias from its target; `const_int` relies on `resolve_type_expression` to find the declaration. Following a constant into another package folds its expression with the caller's locals still active, so a local `M` can shadow the `M` in `other.N :: M`.
- **Unused imports count a package named in either branch of a `when` as used.** `odin check` checks only the taken branch, so it reports `core:hash` in `internal/engine/unload.odin` of the sweep project when every `hash.` sits under a false `when hostabi.CHECKED`. `find_unused_imports` in `src/server/imports.odin` walks both branches on purpose, because organize-imports on save would otherwise delete an import that another build configuration needs.

- **The nested-if merge refuses every named callee it cannot resolve.** `callee_deferred` in `src/server/rols_action_split_merge_if.odin` counts a callee as deferred when neither the whole-file resolve map nor a package-level resolve finds it, and a group call whose overload does not resolve as deferred when any member has a `deferred_*` attribute. A procedure group declared inside a procedure body, or a callee the resolver misses, therefore refuses the merge although the call may be harmless.

## Safe-rename check (`src/server/rols_rename_check.odin`)

- **Known limit: a field rename reads every workspace file once.** The check of a field rename reads the workspace once into memory, then parses only the files that name a carrying type and contain `using` or declare an alias of it, and the files with `#+feature using-stmt`. Before stage S8 it read the workspace once for every type it searched. On a synthetic package of 201 files (200 name the owner type, an alias chain `A2 :: distinct A1`, `A1 :: Foo`, and 20 structs that embed `A2`), the dry-run `ols query rename` of a field went from 0.57 s to 0.21 to 0.25 s, and a refused rename with 20 causes went from 0.49 s to 0.15 s. On tina (`src/io_types.odin:287:2`) it stays at 0.28 s. A cached word index of the workspace would remove the reads.
- **A `using` declaration of a value is not checked.** `check_using_statements` handles `using x` statements only. `using f := make_foo()` compiles without `#+feature using-stmt` and brings the fields of `f` into scope too, so renaming field `y` of `Foo` to `limit` is accepted although a later `_ = limit` in that procedure would then mean `f.limit`.
- **Known limit: implementation requests on a procedure still read every workspace file.** `proc_group_locations` in `src/server/rols_implementation.odin` calls `find_symbol_references`, which reads each file and now parses only a file whose `proc{` group literal lists the procedure's name (`mentions_proc_group`). Stage S8 measured `ols query impl` at 0.24 s before and 0.13 s after on `get_token_range` in this repository, and 0.93 s before and 0.22 s after on `strings.index` in Odin's `core`. A cached word index of the workspace would remove the reads.

## Edits (stage S10)

- **Known limit: "Add ok result" refuses every caller it cannot extend.** `add_ok_to_callers` in `src/server/rols_action_add_ok_result.odin` adds `, _` to `v := f()`, `v = f()`, `a, b := f()` and the `if` init form whatever the arguments, and leaves a statement call alone. It refuses the whole action for a call used as an argument, a return value or an `or_return` operand, because each of those takes exactly the old results. A typed declaration such as `v: int = f()` cannot take a second value, and a procedure used as a value would change its type. A local procedure named anywhere else in its top-level declaration is refused, because its callers are not searched for. `#optional_ok` would keep most of those compiling but changes the result type. Callers are found in the workspace files only, so a caller in a package outside the workspace folders still breaks. A procedure whose body uses `or_return` is refused, because `or_return` assigns the operand's end value to the last result and Odin rejects `Err` to `bool`.
- **Known limit: "Add defer <free>" trusts a call not to keep its argument when the call's result is discarded or holds only scalars.** `escapes_from` in `src/server/rols_action_defer_delete.odin` refuses when the variable, or a value derived from it, is returned, stored, used as a map key, reassigned or passed to a call whose result is kept. A kept result of a non-polymorphic procedure that resolves to only numbers, booleans, runes, enums or bit sets shares nothing, so `n := f(s)` is accepted. A call such as `register(&list, s)` may still store `s` in either case. Only `append`, `append_elem`, `append_elems`, `inject_at`, `assign_at` and `map_insert` are known to store an argument. Proving that a callee does not store its argument needs an analysis of its body, and refusing every call would withhold the action for ordinary calls such as `process(s)`.
- **Known limit: "Unwrap block" refuses an `if` outside a statement list, and counts an unresolved `exit` selector as the end of the flow.** `unwrap_leaves_dead_code` in `src/server/rols_action_unwrap.odin` refuses when `enclosing_stmts` finds no list, such as an `if` that is a `do` body, since the unwrapped statements would need a block of their own. An `else if` without an init statement or an else of its own becomes a plain `else`; one with either is refused. `ends_flow` resolves a called procedure and trusts its `-> !`. A callee that does not resolve counts when it is a selector named `exit`, such as `os.exit(1)` with the import not indexed, so a safe edit may be refused.
- **"Inline procedure call" refuses on any identifier match into another file.** `borrows_from_file` in `src/server/rols_action_inline_proc.odin` checks both directions. Toward the caller it is scope-aware: a name the copy takes from outside the callee refuses only when a local visible at the call, a file-private declaration of the caller's file or an import of another package binds it there. Toward the callee's file it does not track shadowing, so a parameter or local named like a file-private declaration or an import of the callee's file refuses the action. It does not add the missing import for the caller.
- **Known limit: "Inline variable" refuses initializers whose evaluation order it cannot prove.** An initializer moved past a statement must hold no call other than the runtime builtins `min`, `max`, `abs`, `clamp`, `len` and `cap` over an argument that is neither a pointer nor a `cstring`, and the type-only `size_of`, `align_of`, `offset_of`, `type_of` and `typeid_of` (`reads_state` in `src/server/rols_action_inline_variable.odin`). It must also hold no index, slice or deref, no `context`, no selector on a variable or parameter, no read of a global or a `@(static)` local, and no name the resolver misses. A recursive call writes the same static local, so it counts as a global. An initializer that fails this is inlined only into the next statement (`evaluated_in_place`). There, nothing before the use may call, read a global or a static local, or read a local whose address is taken, aliased by a slice or `for &e`, or passed to a `->` call; any plain `=` target is accepted. An `any` or `#by_ptr` argument also exposes a local's address, and this check does not see it. A literal initializer with more than one use is refused, because each copy would be a fresh value and a `[dynamic]` or map literal would allocate once per copy. A read of a `using` field is refused, because it resolves to the field and the action cannot track writes to it through the struct. An unresolved callee name such as `bar` in `bar(v)` is still accepted, because compiling code can only call a procedure there.
- **"Generate test" refuses a result whose zero value needs a package-qualified type.** `result_checks` in `src/server/rols_action_generate_test.odin` spells an aggregate as `T{}` because `testing.expect_value` cannot infer a bare `{}`. For `time.Time` the test file would need the import, so the action is withheld instead. The action is also withheld for a result that `testing.expect_value` rejects as not comparable, such as `any`, a struct holding a slice, a `#raw_union` struct, a `#soa` fixed array or a fixed-capacity dynamic array; a field assertion per member would lift it.
- **"Generate test" deletes every slice, dynamic array and map result.** The stub writes `defer delete(result)` and `testing.expect(t, len(result) == 0)`. A procedure that returns a view into memory it does not own, such as a sub-slice of a global, gets a test that frees memory it must not free; the author edits the stub.
- **"Generate test" leaves out an OS without `core:testing` only when a file builds on nothing else.** `excluded_test_oses` in `src/server/rols_action_generate_test.odin` adds `#+build !js` when another file of the package builds only on js, wasi, orca or freestanding. A package that marks its js support with a file such as `#+build js, linux` gets no line, so a build of that package for js fails on the test file. Neither does a package built for js only because an importer has a `main_js.odin`. The CLI compile gate now catches that case: `main_js.odin` makes it check the importer directory on `js_wasm32`, which builds the edited package and its test file there. The action also reads every file of the package each time a client asks for code actions on a procedure name, unless the test file exists.
- **`rename-package` rewrites a bare package name only as the value of a declaration.** `alias :: old` is rewritten. Any other bare use of the name is left alone because it may be a field or a local.
- **`builtin_without_decl` counts a constant named like a builtin type as a type.** `builtin_without_decl` in `src/server/rols_edit.odin` qualifies a builtin type name only when the package declares that name as a type outside a file-private scope. A constant such as `string :: "x"` is indexed as `.Unresolved`, like a distinct type, so it still counts, and a builtin `string` result prints as `pkg.string`, which does not compile. Telling the two apart needs the declaration's value kind in the index.
- **The ok-flag check resolves a callee's result type with the open file's imports.** `result_kind_in` in `src/server/rols_action_result_handling.odin` resolves `pkg.My_Ok` through `resolve_type_in_package`, which reads the imports of the open document. A selector type whose import name differs between the callee's file and the caller's file can stay `.Other`, or resolve to an unrelated boolean type of the same name and wrongly become `.Bool`.
- **"Inline procedure call" reads an untyped or unresolved literal as a struct literal.** `is_field_name` in `src/server/rols_action_inline_proc.odin` treats `K` in `{K = 1}` as a field name when the literal has no written type or its named type does not resolve, so a map or array key there is skipped by the capture check. Resolving the expected type of an untyped literal would close it.
- **Known limit: "Remove redundant else" refuses an else that ends the flow when statements follow the `if`.** `redundant_else` in `src/server/rols_simplify.odin` would put those already unreachable statements right after the else's terminator, and `odin check` (dev-2026-09) rejects statements after a `return` or `break` in the same block. A field name in a literal, such as `y` in `Point{y = 1}`, still counts as a mention of an else declaration, because a literal key may name a variable.

## CLI queries (`src/cli/rols_cli.odin`, `src/server/rols_find.odin`)

- **Known limit: `check` and `tests` in a directory without `.odin` files cover every package of the root, with one `odin check` per package.** The run gets the 20 s of an editor check for each batch of cores packages, capped at 10 minutes (`gate_check_timeout`), and the packages share no cache, so a large repository takes long. Odin keeps no cache across processes, and one `odin check` takes one package, so the CLI cannot share the work.
- **Known limit: `find` and `tests` treat a `when` condition with a selector as unknown.** `when_known` in `src/server/rols_when_inactive.odin` rejects `pkg.FLAG`, even where the editor's index evaluates it, because `fold_package_when_const` in `src/server/rols_when.odin` reads an unknown name in the other package as false, so a mark from it could be wrong. It belongs with the build-tag and `when` work below.
- **`find` and `tests` treat builtins such as `ODIN_DEBUG` and `ODIN_TEST` as unknown.** `when_known` does not seed them, so a branch after such a condition stays unmarked. Seeding `ODIN_DEBUG` from `-debug` in `checker_args`, and `ODIN_TEST` as true for `tests`, would decide them.
- **Known limit: `check DIR` still runs `odin check` over the gitignored files of `DIR`.** Only the lints follow the workspace filter. `odin check` has no flag to leave out one file of a package, so an error in a gitignored file is reported.
- **`tests DIR` filters files and sibling constants for different targets without a `-target:`.** `find_tests` in `src/server/rols_tests.odin` keeps the files that `builds_on` accepts for `base_target` (the host), while `build_when_package` in `src/server/rols_when_inactive.odin` reads the sibling constants of the files that `host_target()` builds (the profile `os` and `arch`, else the host). With a profile target and no `-target:`, the two sets can differ.
- **`when_known` accepts values that `register_when_const` cannot fold.** A comparison of two strings such as `"a" < "b"`, or `1 && 2`, passes `when_known`, so `fold_plain_consts` counts the constant as folded although `consts` never gets it, and a condition that uses it reads false while it counts as known.
- **The editor folds package constants in map order.** `register_when_consts_from_globals` in `src/server/when.odin` keeps the first value it registers for a name and reads a name it has not folded yet as false, so with `ON :: !FLAG` and `FLAG :: true` it can fold `ON` as true, depending on the order of the globals map. `inactive_when_decls` now folds the constants it trusts through `fold_plain_consts` first, in dependency order; the index and `collect_document_globals` still use the map order.

## CLI compile gate (`src/cli/rols_apply.odin` `run_edit`)

- **A touched directory that is not linked by imports to the one that needs a target is not checked on it.** Before per-target directories, every extra target checked every touched package. Now a check covers only the directories whose files need its target and their importers. So when an edit touches two directories, and neither imports the other, a `when ODIN_OS == .X` branch in one directory is not checked on X unless a file of that directory needs X. `checker_targets` still checks every package on its targets.
- **A `checker_variants` entry runs only on the current target.** `with_variants` in `src/cli/rols_gate.odin` adds one check per entry without a `-target:`, so code that needs both the variant's define and another target, such as tina's simulation code on `linux_amd64`, is not gated. The drop rule of `gate_baseline` also does not apply to a variant check, so a variant whose package does not build on the current target keeps reporting its baseline errors.
- **Each extra target walks the workspace again.** `gate_targets` in `src/cli/rols_gate.odin` calls `importer_dirs` once per target that a file needs, and each call reads the imports of every workspace file, after the walk `run_edit` already did. One import graph built once would serve every target; the cost was not measured. The checks cost more than the walk: an edit to an untagged file in a package with OS siblings (`x_windows.odin`, `x_linux.odin`, `x_js.odin`, …) runs one extra check per sibling OS that the current target does not build, each over the package and its transitive importers and each with its own `gate_check_timeout` budget, before and after the write. With all six desktop OSes, js, wasi, orca and freestanding present on a darwin host, that is 9 extra checks per run. In the worst case, a package that every workspace package imports, each check covers the whole workspace and can take up to 10 minutes.
- **Known limit: an extra target drops a package that builds there but reports an error inside a core generic.** `gate_baseline` in `src/cli/rols_gate.odin` skips a package on an extra target when its baseline check there names a file outside the workspace, and an error that a workspace call raises inside a `core:` generic names a core file, so that package loses its gate on that target. Dropping a package costs a second baseline run of that target. A changing error set is handled by `run_edit` instead: it absorbs an error that the check before the write missed (the check of the original code reports it) and an error that one check after the write reports by chance (the second check after the write does not).
- **Known limit: an error that both checks after the write report by chance still rolls back the edit.** `run_edit` in `src/cli/rols_apply.odin` runs one extra check of every package after the write and treats an error as new when both report it and the check of the original code does not. A flake seen in about 1 of 12 runs, such as `core/sync/chan/chan.odin:382` "'where' clause evaluated to false" in ols, would roll back about 1 edit in 144 if the runs are independent; this was not measured. More reruns would lower that at the cost of a check each.
- **Known limit: the rename rewrite uses lines, not columns.** `on_edited_line` in `src/cli/rols_gate.odin` lets a before error on a line the rename edits match the renamed form, so an unrelated error on the same line still can. Columns cannot narrow it: odin places an error at the start of the expression or statement it reports, not at the renamed identifier (`s = 1 + old_name(1)` reports at the `1`). An error whose position is on another line of a multi-line call is not rewritten.

## Large-file performance (stage S15)

- **Known limit: opening a 2 MB file takes 1.3 to 1.5 s.** On `core/rexcode/isa/ppc/mnemonic_builders.odin` (13,308 declarations), `didOpen` followed by a hover takes 1.31 to 1.52 s, and 0.19 s with `enable_diagnostics` off. The whole-file resolve that the lints start (`resolve_entire_file`) costs about 1.1 to 1.2 s, and parsing and the hover the remaining 0.2 s. Stage S8 removed a second `run_lints` call from `didOpen` (`document_refresh` already lints): before it, the same open and hover took 1.42 to 1.43 s. The whole-file resolve is shared: unused imports, inlay hints and semantic tokens read the same cached map, so inlay hints after the open add almost nothing (1.30 to 1.42 s in total). Earlier stacks showed no single hot spot: `clone_node`, `resolve_function_overload`, `create_uri` and `store_local` each hold a few percent. After the open, documentSymbol answers in 1.36 to 1.39 s in total and a code action in 1.54 to 1.58 s. The overload fixes of stage S3a left it unchanged (1.36 to 1.60 s against 1.36 to 1.91 s in paired runs).
- **Known limit: code actions recompute `lint_fixes`, `simplifications` and `stdlib_matches` per request.** A code action on the 2 MB file costs 0.2 s or less beyond the open, so no cache was added. A cache keyed by document version would also need invalidation on every reparse and every config change.

## Test harness (`build.sh`)

- **A test that panics or faults can hang in some agent sandboxes (found in S16).** There the fault handler that the Odin runner relies on (`stop_test_callback` in `core:testing`) is not reached, and the faulting thread re-traps forever: `invert_if_early_exit_do_body` at `c5c8fa27^` panicked on a bounds check and then spun, and a C program with `SIGSEGV` and `SIGTRAP` handlers behaved the same. This is an environment issue, not a rols bug. On 2026-10-06 a scratch test with `panic("boom")` failed normally in about 0.1 ms, so not every session is affected. `ROLS_TEST_TIMEOUT=SECONDS ./build.sh test` (or `single_test`) now bounds a hang: on timeout it sends SIGKILL to the process group of `odin test`, its `tests` child included, and exits 1. Set it lower than any outer timeout (GNU `timeout`, a CI cancel, an agent tool limit): an outer kill of the `build.sh` process group does not reach the test group. Without the variable a hang still never ends, and a plain `kill` of the run does not stop it, because the runner's first SIGTERM only sets a flag. `kill -9` on the `tests` process does stop it.
- **`for x in m[k]` over a map index loops forever when `k` is missing (Odin dev-2026-09).** S16 grepped `src/`, `tests/` and `tools/` for ranges over an index expression and found no remaining site over a map (`importer_dirs` was already rewritten; `untyped_map` and `diagnostics` are enum-indexed arrays, and the rest index slices or fixed arrays). `lint_loops` reports the pattern. Candidate upstream Odin issue, not filed. Repro:

  ```odin
  package main

  main :: proc() {
  	m := make(map[string][dynamic]string)
  	for d in m["x"] { _ = d } // never ends
  	l := m["x"]
  	for d in l {} // ends
  }
  ```

## Whole-file resolve (`src/server/file_resolve.odin`)

- **Known limit: a failed overload resolution stays cached per mode within a declaration.** `resolve_function_overload` caches each result, failures included, in `ast_context.call_expr_recursion_cache` with the `OverloadMode` it resolved in (`src/server/rols_resolve.odin`), and the whole-file walker clears the cache between top-level declarations. A later resolution of the same call in the same mode inside that declaration returns the failure, even where it would resolve. No reproducing case is known since `get_local` stopped giving the initializer of a global the locals of a procedure that uses the global. Shapes tried: a group call with an implicit selector argument (`g(.A, 1)` over `f1(k: Kind, v: int)` and `f2(k: Kind, v: int, w := 0)`), a tie between members with different results whose call is stored in a local that is used again, references and hover on an implicit selector in such a call, and a field selector on the call result. In those shapes the walker resolved the call in the `All` mode only, and hover on the implicit selector did not read the cached call.
- **The binary walker leaves `binary` on the last nested expression it popped.** `resolve_binary_expr` pushes both operands and pops the right one first, so in `.X == a + b` the implicit selector `.X` is resolved with `binary` set to `a + b`. `resolve_implicit_selector` then finds the cursor outside that expression, and `.X` does not resolve, so references of `X` miss it. `a + b == .X` resolves.
- **The whole-file resolve now allocates its temp memory from the document cache arena.** This keeps the cached symbols valid after the request frees temp memory. It also retains the resolve scratch until the document is reparsed or caches are invalidated. Measured `symbol_cache_arena.total_used` after `resolve_entire_file`: 23.9 MB without the swap and 29.1 MB with it for a 100 KB file (+5.2 MB, +22%), and 57.7 MB and 70.5 MB for a 250 KB file (+12.9 MB, +22%). A targeted copy of the escaping data (`pkg` strings, docs, synthesized nodes such as `wrap_pointer`) would remove the extra share. It needs an audit of every default `context.temp_allocator` that a cached symbol can point to.

## Overload resolution and hover (`src/server/analysis.odin`, `src/server/hover.odin`)

- **A tie for one member picks the first even when the members differ.** `resolve_function_overload` returns no member for a tie whose results differ only when the call result is wanted. With `resolve_specific_overload` set it still takes the first member: an implicit selector or a completion in an argument then reads that member's parameter even where the tied members take different types there, and `f()()` (`resolve_call_expr`) reads that member's results.
- **A procedure and a global inside the same top-level `when` share a declaration index.** `in_local_top_level_decl` in `src/server/rols_resolve.odin` compares top-level declarations, and a top-level `when` statement is one declaration. The initializer of a global declared inside the same `when` as a procedure therefore still sees the locals of that procedure.
- **The argument-count lint still needs its group guard.** `lint_calls` in `src/server/rols_lint_calls.odin` skips a group call that resolves to a member named differently from the call, because overload resolution keeps a member that needs more arguments than the call passes. With `one :: proc(a, b: int)` and `two :: proc(a: Missing)` in a group `g`, `g(1)` resolves to `one`. Filtering members by their required count would let the guard go, but completion and signature help resolve calls that are still being typed.
- **The member of `offset_of` is recognized by the callee name.** `offset_of_member_arg` in `src/server/rols_offset_of.odin` treats any call named `offset_of` or `offset_of_member` with two arguments as the builtin. A user procedure that shadows either name loses resolution of its second argument in references, rename, hover and go-to-definition.

## Build tags and `when` (`src/server/build.odin`, `src/server/when.odin`)

- **Files excluded for the host are not indexed, so a call from an excluded file resolves to the host's sibling.** The open file's own declarations win, and the lints treat an excluded file like an inactive `when` branch: the lints in `resolving_lints` (`src/server/rols_lint.odin`), such as ignored-result, printf and call-arity, report nothing in such a file, for example `foo_windows.odin` on darwin. The test `resolving_lints_skip_file_the_host_does_not_build` pins it. Navigation from such a file still goes to the wrong platform's declaration (for example `socket_linux.odin` on darwin reaches `errors_posix.odin`). A fix would index excluded files per target.
- **The naming, deprecated and unused-parameter lints, and the use-stdlib hints, still resolve names in inactive `when` branches.** `resolving_lints` in `src/server/rols_lint.odin` leaves the three lints running there because their tests expect reports in such branches and they resolve only a kind, an attribute, or a procedure passed as a value. They see fallback symbols there, which is right for a name that only that platform declares. The use-stdlib hints (`src/server/rols_lint_use_stdlib.odin`) run outside the lint walker, so they see inactive code and fallbacks with no check at all. A platform variant with a different kind or deprecation, or a same-named variable, can still give them a wrong answer in that code.
- **In active code a name that resolves to a fallback reads as unresolved in the lints.** `lint_symbols` drops such nodes, and some lints treat a missing node as a local or a constant: `is_local_store` in `src/server/rols_lint_dead_store.odin` treats it as a local, and `is_constant_expr` in `src/server/rols_lint_bool.odin` as a constant. Active code reaches a fallback only when odin would report `Undeclared name`, or when the `when` evaluator misjudges a condition as false, so the lints can then report on the wrong assumption.
- **Active code that names an inactive-only declaration resolves it.** Hover, definition and rename reach a `Fallback` symbol from code that the host builds, where odin reports `Undeclared name`. Completion does not offer it, and in active code the lints skip it (`lint_symbols` and the unused-declaration lint). Two fallbacks of one name keep the first one indexed. With `when A { T :: struct { a: int } }` in one file and `when B { T :: struct { b: int } }` in another, code under `when B` in a third file can resolve `T` to the first file's declaration.
- **A `when` condition reads `pkg.NAME` through constants of that package only.** `fold_package_when_const` in `src/server/rols_when.odin` folds names in the value through constants of the same package. A selector, which reads a third package, is unknown: as the whole value it makes the condition false, and inside a named constant it makes that name read as false, so with `ON :: !MID` and `MID :: other.X` the constant `ON` folds to true. A mutable global and a cycle of constants also read as false.
- **`#+build` project names are matched with an empty project name**, so a `#+build !name` line does not exclude anything. A positive `#+build name` line reads as built nowhere: `builds_together` in `src/server/rols_check_targets.odin` then drops such a sibling from the rename collision scan, so a `NEW` declared there is not reported.
- **The field rename of a per-platform struct changes one variant only.** `declaration_variants` in `src/server/rols_variants.odin` serves rename, reorder-params, find references and the `unused-parameter` fix, but a field rename resolves the field through one struct declaration, so the same field of the struct's other platform variants keeps its name. "Remove parameter", "Introduce parameter" and "Add ok result" are withheld for a procedure with variants rather than changing them all.
- **The rename collision scan of sibling files reads file build tags and names only.** `check_collisions` in `src/server/rols_rename_check.odin` reports `NEW` in a sibling that some OS and architecture builds together with the declaration or a variant (`builds_together` in `src/server/rols_check_targets.odin`), and drops an index hit in a file that never builds with them. `when` conditions are not evaluated, so a `NEW` under `when ODIN_OS == .Linux` in a generic file still blocks renaming a declaration of `f_windows.odin`.
- **Variants are identified without evaluating `when` conditions.** Two declarations in different `when` statements of host-built files count as variants even when the conditions overlap, and two declarations in excluded files for the same target count as variants of the host's declaration. Both shapes are redeclarations that odin rejects on some target, so renaming them together is harmless, but such a duplicate is not reported.
- **`move_decl` matches imports by the selector base, not by resolution.** `stale_imports` in `src/server/rols_move_decl.odin` counts `strings.f` on a local `strings` elsewhere in the file as a use, so the import stays after its only real user moves out. `used_imports` skips a base that the moved procedure declares anywhere inside it, so a struct field or a local of another block spelled like the import also drops the import from the target. Resolving each base to a `.Package` symbol would fix both.
- **`move_decl` still compares `#+build` project names literally.** Two spellings of one project-name constraint count as different, so the move is refused.

## Poly call result symbols (`src/server/rols_edit.odin`, `src/server/analysis.odin`)

- **Poly resolution gives a call result the package of its type argument.** `size_buf := unwritten(b.buf)` with `unwritten :: proc(d: [dynamic]$E) -> []E` and `b: bytes.Buffer` resolves `size_buf` to a `[]byte` symbol whose package is `bytes`, not the document's. `symbol_type_text` guards against it at the consumer (a Variable or Constant symbol named like the variable takes the document package), so the add-explicit-type action and the inlay hints print `[]byte`. The root cause is still in the resolver, and any other consumer of `symbol.pkg` can see the wrong package. Hover on such a variable showed `c1.size_buf: []byte` in a quick check, so it is not visibly affected.
